# 야시장 오늘의 매대판 — BM 캔버스 (v1, 결정 항목 포함)

> **기준 안내**: 수업용 가상 데이터 기준입니다 (`ax/ideas_top3.md` 머리말).
> **표기 규칙**: 숫자 앞에 `확인값`(출처 있음) 또는 `가정값`(출처 없음)을 붙입니다. 재료에 없는 칸은 `가정`으로 표시합니다.
> **결정 표시**: `결정`은 재료가 없어 Claude가 정한 내용입니다. 바꾸려면 이 파일의 해당 칸을 고치면 됩니다.
> **valuechain 자료**: 더본코리아 자료라 사실 근거로 쓰지 않았습니다 (구조 참고만 가능).

## 캔버스 (9칸)

| 칸 | 내용 |
|---|---|
| 1. 고객 세그먼트 | 서문시장 야시장의 **방문객**: 현금 없이 방문한 구매자 (대구 거주 직장인 · 주말 방문 가족 · 관광객). 근거: `painpoint/painpoint_def.md`, 사용자 메모. **지불자**: 야시장 상인회. 근거: 사용자 설문조사 |
| 2. 가치 제안 | 매대 카드 화면에서 **결제 수단**(P1), **오늘 영업 여부**(P2), **품절 메뉴**(P3)를 방문 전에 확인. 영업 여부는 상인 입력 기준이라 정확도 미확인 (△). 대기 시간은 제외 (`결정`). 대체 수단: 지도 앱 · 블로그 · SNS (사용률 미확인). 근거: `painpoint/painpoint_def.md`, 사용자 교차 확인 답변 (대화 기록) |
| 3. 채널 | 야시장 입구 안내판 + 매대별 QR 코드. 근거: 사용자 메모 |
| 4. 고객 관계 | 방문객이나 상인이 틀린 정보를 신고하면 접수 후 수정하는 **신고형 관계**. 상인에게는 입력 안내 · 수정 결과 알림을 보냄. 근거: 사용자 메모 · 측정: 신고 건수, 처리 기한 준수율 (`결정`) |
| 5. 수익원 | 야시장 상인회의 **정액 구독**. 매대 1곳당 월 **5천~1만 원** (`가정값`, 사용자 설문 보고, 원자료 파일 미확인). `ax/ideas_top3.md`는 1만 원으로 단정해 범위와 다름. 기준값 월 7,500원 (`가정값`, 범위 중간). 매대 80곳 (`가정값`)이면 월 40만~80만 원 (`가정값`) |
| 6. 핵심 자원 | 매대 정보 카드 **자동 정리 AI** (사진 · 한마디에서 정보 추출), 상인 입력 데이터 (D5, 서비스 운영 후 생김), 상인회 운영 공지 (D2), **사무국 수정 기록 (학습 데이터, `결정`)**. 근거: `ax/ideas_top3.md`, `ax/risk_check.md`, 사용자 메모 |
| 7. 핵심 활동 | ① 상인 정보 입력 안내 → ② AI가 결제 수단 · 영업 여부 · 품절 메뉴를 뽑아 카드로 정리 → ③ 게시 전 확인 (확인 주체: 상인회 사무국, `결정`) → ④ 신고 접수 후 수정. 근거: `ax/ideas_top3.md`, `ax/risk_check.md`, 사용자 메모 |
| 8. 핵심 파트너 | 야시장 상인회 (입력 안내 · 게시 확인 · 신고 접수 창구). 근거: 사용자 메모, 설문조사 |
| 9. 비용 구조 | ① 상인 입력 안내 인건비, ② 게시 전 확인 인건비, ③ AI 처리 비용. 두 인건비 비율은 **2 : 1** (입력 안내 40시간, 게시 확인 20시간 / 월, 모두 `가정값`, `결정`). 시급 12,000원 (`가정값`). 인건비 월 약 72만 원 (`가정값`) = 입력 48만 + 확인 24만. AI 처리 비용은 미정 |

| 손익분기 매대 수 (7,500원 기준) | 96곳 | 가정값 |

## 수익 · 손익 점검 (`가정값` 기준)

| 매대 수 | 구독료 7,500원 기준 월 수익 | 월 인건비 | 수익 - 인건비 |
|---|---|---|---|
| 80곳 | 60만 원 | 72만 원 | -12만 원 |
| 96곳 | 72만 원 | 72만 원 | 0원 (손익분기) |
| 120곳 | 90만 원 | 72만 원 | +18만 원 |

- 손익분기: 구독료 7,500원이면 **96곳**, 1만 원이면 **72곳**, 5천 원이면 **144곳**입니다.
- 80곳에서는 적자가 나므로 매대 수 확대 또는 인건비 절감이 필요합니다. AI 처리 비용은 아직 빠져 있습니다.

## 결정 사항 (재료 없음 → Claude 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 수익 모델 | 상인회 정액 구독 1개만 사용 | 설문으로 지불 의사 확인됨. 나머지 후보는 `bm/revenue_option.md`에서 제외 · 보류 |
| 상단 노출 광고 | 제외 | 노출 순서가 바뀌면 편향 리스크 발생 (`ax/risk_check.md`) |
| 방문객 유료 알림 | 보류 | 무료 카드 화면과 기능이 겹침. 방문객 수 확인 후 재검토 |
| 매대 등록비 | 제외 | 상인 부담이 커져 등록이 줄 수 있음 |
| 상권 데이터 판매 | 보류 | 개인정보 · 상인 동의 필요 (`ax/risk_check.md`) |
| 게시 전 확인 주체 | 상인회 사무국 1명 | 상인회가 핵심 파트너이므로 사무국이 맡음 |
| 정보 정렬 기준 | 영업 중인 매대 우선, 이후 매대 번호 순 | 광고 없이 편향 최소화 |
| 틀린 정보 처리 기한 | 신고 접수 후 영업일 1일 이내 수정 (안) | 재료에 없음. 운영 후 조정 |
| AI 정리 오류 책임 | **미정** (임시 안: 사무국이 확인 · 수정) | `ax/risk_check.md` 책임 소재 미정, 결론 없음 |

## 리스크 · 조건 (`ax/risk_check.md` 기준 + 결정)

- **개인정보**: 조건부 통과. 사진에 얼굴 · 계좌번호가 찍히면 게시 전 확인 단계에서 가림.
- **저작권**: 해당 없음 (상인이 직접 찍은 사진).
- **편향**: 조건부 통과. 정렬 기준을 공개 (위 결정 사항).
- **책임 소재**: 미정 (임시 안: 사무국 확인 · 수정). 시범 운영 후 결정.
- **수익 리스크**: 80곳에서 적자 (위 손익 점검). 매대 수 또는 인건비 조정 필요. 미납 · 해지율, 초기 투자 · 운영 자금 미산정.
- **경쟁 리스크**: 경쟁사 정보 없음. 카드 화면은 지도 앱 · SNS로 대체될 수 있고, AI 정리 기능은 일반 AI로 복제 가능.
- **데이터 리스크**: 상인 입력 데이터(D5)는 서비스 운영 후에 생김. 초기 카드 부족 (콜드 스타트). 학습 효과 수치 없음.
- **상인회 리스크**: 지불자가 상인회 하나. 예산 확보 미확인, 이탈 · 계약 조건 없음.
- **영업 여부 정확도**: 사진만으로 불확실 (△). 정렬 기준이 입력에 기대므로 미입력 매대가 불리.
- **운영 리스크**: 게시 전 확인 담당이 사무국 1명. 담당자 부재 시 서비스 중단.
- **외부 데이터**: 지도 앱 데이터(D3) 수집 약관 미확인 (`research/data/sources.md`).

## 학습 루프 (이용 → 데이터 → 개선 → 결과, `결정` · 주기 주 1회 `가정`)

| 단계 | 할 일 | 측정 (가정) |
|---|---|---|
| 이용 | 카드 열람, 신고 클릭, 상인 입력 응답 기록 | 열람 수, 신고 건수, 입력 완료율 |
| 데이터 | AI 추출 결과와 사무국 수정 기록을 쌓음 (수정 기록 = 정답 데이터) | 수정률 (AI 결과 중 사람이 고친 비율) |
| 개선 | 수정률이 높은 항목부터 추출 규칙, 프롬프트, 안내 문구 수정 | 항목별 정확도 변화 |
| 결과 | 신고 건수, 확인 시간, 헛걸음 · 재대기 건수 확인 후 다음 이용에 반영 | `painpoint_def.md` 측정 신호 |

- 개인정보: 학습에 쓰는 상인 사진은 재사용 동의를 받고, 얼굴 · 계좌번호는 저장 전에 가림 (`ax/risk_check.md`).

## AX 블록: 학습 루프 데이터 흐름 (`결정`, 재료 없음)

| 단계 | 데이터 흐름 | AI 역할 |
|---|---|---|
| ① 데이터 원천 | 상인 입력 사진 · 한마디 (D5), 사무국 수정 기록, 신고 내역, 방문객 열람 로그 | — |
| ② 이용 | 카드 열람 · 신고 · 입력 응답이 ①로 쌓임. 영업 중 매대 우선 정렬 | 추천 |
| ③ 데이터 | AI 추출 결과 저장, 사무국 수정률 계산 (정답 데이터) | 예측 · 생성 결과 저장 |
| ④ 개선 | 추출 규칙, 프롬프트, 안내 문구 수정. 수정안 작성 | 생성 (최종 반영은 사람) |
| ⑤ 결과 | 신고 건수, 확인 시간, 헛걸음 건수 측정. 다음 주 원천 데이터를 바꿈 | — |

- 루프 주기: 주 1회 (`가정`).
- 흐름의 핵심: ⑤ 결과가 다시 ①을 바꾸므로, 수정 기록을 남기지 않으면 루프가 끊깁니다.

## AI 자동화 가능 영역

> **표기**: ◎ AI가 자동 처리 · ○ AI가 보조하고 사람이 최종 확인 · △ 일부만 가능, 사람 입력 필요 · ✕ 사람만 가능
> 재료에 없는 자동화 효과(시간 · 비용 절감률)는 `미정`입니다.

| 칸 | 항목 | 표기 | 이유 |
|---|---|---|---|
| 2. 가치 제안 | 결제 수단 · 품절 메뉴 카드 표시 | ◎ | 사진 · 한마디에서 텍스트를 뽑아 카드로 정리하는 것이 이미 AI 처리 설계 (7번 ②) |
| 2. 가치 제안 | 오늘 영업 여부 | △ | 사진만으로는 영업 여부를 확실히 알 수 없음. 상인 입력 또는 시간 기준 판정 필요 |
| 3. 채널 | 매대별 QR 코드 생성 | ◎ | 매대 등록 정보에서 QR을 자동 생성 가능 (규칙 기반, AI 불필요) |
| 4. 고객 관계 | 신고 내용 분류 · 중복 확인 | ◎ | 신고 문장을 정보 유형별로 나누고 같은 신고를 묶을 수 있음 |
| 4. 고객 관계 | 신고 내용에 따른 실제 수정 | ○ | AI가 수정안을 만들고, 상인 확인 후 사무국이 반영 |
| 6. 핵심 자원 | 매대 정보 카드 자동 정리 | ◎ | 7번 ②와 같음 (핵심 자원 자체) |
| 7. 핵심 활동 ① | 상인 정보 입력 안내 (메시지 · 질문) | ○ | 입력 안내 문구와 알림 발송은 자동화. 상인이 어려워하는 경우는 사람이 응대 |
| 7. 핵심 활동 ③ | 게시 전 확인 | ○ | AI가 얼굴 · 계좌번호 · 누락 항목을 먼저 표시하고, 사무국이 최종 확인 (`ax/risk_check.md` 개인정보 조건) |
| 7. 핵심 활동 ④ | 정렬 기준 적용 (영업 중 우선, 번호 순) | ◎ | 규칙 기반 자동 정렬 (AI 불필요) |
| 5. 수익원 | 월 구독료 청구 · 납부 확인 | ◎ | 자동 청구 (AI 아님, 자동화 도구 사용) |
| 9. 비용 구조 | 게시 전 확인 인건비 | ○ | AI 사전 검사로 확인 시간이 줄 수 있음. 줄어드는 비율은 `미정` |
| 9. 비용 구조 | 상인 입력 안내 인건비 | ○ | 자동 안내로 줄일 수 있음. 줄어드는 비율은 `미정` |
| 9. 비용 구조 | AI 처리 비용 | ✕ | AI 자체 운영 비용이므로 자동화 대상이 아님 (비용 금액 미정) |
| 1. 고객 세그먼트 | 방문객 · 지불자 선정 | ✕ | 사람이 정하는 사업 판단 |
| 8. 핵심 파트너 | 상인회 관계 · 설득 | ✕ | 사람 간 신뢰가 필요함 |

### 요약

- **AI 완전 자동 (◎)**: 카드 정리, QR 생성, 신고 분류, 정렬, 구독 청구. 주요 자동화 대상은 매대 카드 정리입니다.
- **사람 최종 확인 필요 (○)**: 게시 전 확인, 신고 수정, 입력 안내. 여기서 인건비를 줄이는 것이 핵심입니다.
- **사람만 가능 (✕)**: 파트너 관계, 고객 선정, AI 운영 비용.

## 근거 · 선택 이유

1. **선택 이유**: 임팩트 4.5 · 실현성 4.0 (`확인값`, `ax/opportunity_matrix.csv`).
2. **문제 근거**: P1 결제 수단 정보 없음, 점수 60 (`판정값`, 가상 데이터, `painpoint/painpoint_def.md`). P2 · P3도 가치 제안에 포함.
3. **고객 근거**: J1 (줄 서기 전 결제 수단 확인), J2 (현금 없이 방문했을 때 포기하지 않기). `ax/jtbd.md`.
4. **지불 의사 근거**: 상인회 월 5천~1만 원 (`가정값`, 사용자 설문 보고, 원자료 미확인).
