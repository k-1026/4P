사이트가 처리하는 규칙
- 도로명주소나 지번주소가 **"대구"로 시작하지 않는 행은 버림** → 주소 열을 꼭 지정
- 인허가일자를 읽을 수 없는 행은 버림
- 폐업 판단: 영업상태명에 "폐업"이 있거나, 영업상태코드가 `03`이거나, 폐업일자가 있고 상태가 영업/정상이 아니면 폐업
- 좌표가 비었거나 0 이하면 지도에 안 나옴 (목록에는 나옴)
- 영업 중 가게의 영업연수는 **올린 날(오늘)** 기준으로 계산
- 올린 데이터에는 `주의표시`(지위승계 의심)가 붙지 않음

### 6-2. 방법 B — `daegu.json` 형식

가게 한 곳을 한 줄로 두지 않고, 항목마다 가게 수만큼의 목록을 따로 두는 구조입니다. `i`번째 가게의 정보는 각 목록의 `i`번째 값입니다.

| 키 | 형식 | 뜻 | 원본에서 만드는 법 |
|---|---|---|---|
| `snap` | 문자열 | 데이터 기준일 (예: `2026-10-28`) | 데이터갱신시점 최댓값 |
| `src` | 문자열 | 출처 이름 | 고정 문구 |
| `types` | 목록 | 업태 이름 목록 (현재 29종) | 업태구분명의 고유값 |
| `gus` | 목록 | 구·군 이름 목록 (9개) | 개방자치단체코드 → 3-1 표 |
| `dongs` | 목록 | 동 이름 목록 (현재 219개) | 주소 괄호 안의 동 이름 |
| `n` | 목록 | 상호명 | 사업장명 |
| `t` | 숫자 목록 | 업태 번호 (`types`에서 몇 번째인지, 0부터) | 업태구분명 |
| `g` | 숫자 목록 | 구·군 번호 (`gus`에서 몇 번째인지) | 개방자치단체코드 |
| `d` | 숫자 목록 | 동 번호 (`dongs`에서 몇 번째인지) | 주소 |
| `s` | 숫자 목록 | 영업 시작일 = 1970-01-01부터 센 **날수** | 인허가일자 |
| `e` | 숫자 목록 | 폐업일 = 같은 방식의 날수, **영업 중이면 `-1`** | 폐업일자 |
| `x`, `y` | 숫자 목록 | EPSG:5174 좌표 (소수점 버림), **없으면 `0`** | 좌표정보(X), (Y) |
| `a` | 목록 | "대구광역시 ○○구" 뒤의 주소 (화면에서 앞부분을 붙임) | 도로명주소 (없으면 지번주소) |
| `w` | 숫자 목록 | `1`이면 주의 표시(지위승계 의심) | 이재훈 분석의 '주의' 칸 |
| `la`, `lo` | 숫자 목록 | 위도·경도를 줄여 저장한 값으로 보임 (예: 872526 → 35.872526) | 좌표 변환 결과 — **사이트 코드는 쓰지 않음** |

주의
- 사이트 코드에 기준일이 **2026-10-28로 고정**되어 있음 → 방법 B로 다른 날짜 데이터를 넣으면 `snap`만 바꿔서는 화면의 기준일과 영업연수 계산이 바뀌지 않음. 이건협에게 코드 수정 요청 필요
- `la`·`lo`는 사이트가 읽지 않으므로 방법 B에서 빼도 됨. 사이트는 `x`·`y`를 읽어 화면에서 직접 위도·경도로 변환함
- 기획서 3-6에서 "위도·경도 열 사용 불가"라고 한 값이 이 `la`·`lo`와 같은 범위 → 버린 값이 아니라 줄여 저장한 값일 가능성 (**확인 필요**)
