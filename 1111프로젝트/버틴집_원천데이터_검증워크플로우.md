## 2. 전체 워크플로우

```
[원천 확보] → [수집] → [정제] → [좌표] → [분류] → [계산] → [결과 검증] → [산출] → [공개]
    ↑           G1        G2       G3       G4       G5          G6          G7
    └──────────────────── 월 1회 갱신 루프 (G8) ────────────────────────────────┘
```
G1~G8은 각 단계 끝의 **통과 조건(게이트)**입니다. 통과하지 못하면 표시된 단계로 돌아갑니다.

| 단계 | 하는 일 | 입력 | 출력 | 담당 |
|---|---|---|---|---|
| 0. 원천 확보 | D1~D10 다운로드·발급, 항목 설명서 확보 | — | `raw/` 원본 (읽기 전용) | 이재훈 · 손효민 |
| 1. 수집 | 원본 읽기, 행 수·열 구조·기준일 기록 | raw | 수집 기록표 | 이재훈 |
| 2. 정제 | 결측 제외, 중복 정리, 날짜 형식 통일, 30일 하한 표시 | raw | `processed/정제.csv` | 이재훈 |
| 3. 좌표 | X·Y → WGS84 변환, 결측 좌표 주소로 보완 | 정제본 | `processed/좌표.csv` | 이재훈 |
| 4. 분류 | 업태 매핑, 메인 메뉴 추정, 프랜차이즈 표시, D2·D3 합치기 | 좌표본, D6·D9 | `processed/분류.csv` | 이재훈 |
| 5. 계산 | 영업연수, KNN(k=10), 중앙값 분모, ε 평탄화, 생존배수, 상위 % | 분류본 | `output/결과.csv` | 이재훈 · 이건협 |
| 6. 결과 검증 | 백년가게 비교, 민감도, 표본 직접 확인 | 결과, D5 | 검증 보고서 | 손효민 · 이찬영 |
| 7. 산출 | 화면용 JSON 생성, 배지 대상 표시 | 결과 | `output/stores.json` | 이건협 |
| 8. 공개 | 웹페이지 반영, 문구·한계 표시 점검 | JSON | 배포 | 이건협 · 이찬영 |

원칙 (9-1, 14-1): 원본은 수정하지 않고, 단계마다 결과를 따로 저장하며, 실행할 때마다 기준일·행 수를 기록합니다.

## 3. 데이터 검증 루프

각 루프는 **점검 → 판정 → (실패 시) 되돌아가기 → 기록** 순서로 돕니다. 기준 값 중 기획서에 없는 것은 **제안**이며, 첫 실행 결과를 보고 팀이 확정합니다.

### 루프 A. 수집 검증 (G1) — 원본을 받을 때마다

| 점검 | 통과 기준 | 실패 시 |
|---|---|---|
| 행 수 | 지난번과 비교해 ±5% 이내 (**제안**) | 다시 내려받기, 제공처 공지 확인 |
| 열 구조 | 열 이름·개수가 지난번과 같음 (현재 14열) | 열 대응표 수정 후 재수집 |
| 인코딩 | UTF-8로 읽힘, 한글 깨짐 없음 | 인코딩 변환 |
| 기준일 | 파일의 가장 최신 날짜를 기록, 서비스 기준일과 차이 기록 | 기준일 결정 |
| 지역 | 구군 값이 대구 9개 구·군만 | 다른 지역 행 제외 |

### 루프 B. 정제 검증 (G2)

| 점검 | 통과 기준 | 실패 시 |
|---|---|---|
| 필수 값 | 영업시작일 없는 행은 제외 목록에 따로 저장 (현재 14건) | — |
| 날짜 순서 | 폐업일 < 영업시작일 0건 | 해당 행 확인 후 제외 |
| 미래 날짜 | 기준일보다 뒤 날짜 0건 | 해당 행 확인 |
| 상태 일치 | 폐업 건은 폐업일자 있음, 영업 건은 비어 있음 | 상태 열 기준으로 보정 |
| 중복 | 상호명+주소 같은 행을 ① 같은 날짜 완전 중복 ② 재인허가 ③ 다른 지점으로 분류, ①만 제거 (**제안**) | 규칙 수정 |
| 제외 비율 | 제외한 행이 전체의 5% 이하 (**제안**) | 정제 규칙이 너무 엄한지 재검토 |

### 루프 C. 좌표 검증 (G3)

| 점검 | 통과 기준 | 실패 시 |
|---|---|---|
| 범위 | 변환한 좌표가 대구 범위 안 (대략 위도 35.6~36.3, 경도 128.3~129.0, 군위군 포함) | 좌표계 설정(EPSG) 재확인 → D4 |
| 구·군 일치 | 좌표로 찾은 구·군 = 주소의 구·군, 일치율 99% 이상 (**제안**) | 불일치 행을 목록으로 뽑아 확인 |
| 표본 대조 | 무작위 50곳을 카카오 주소 검색 결과와 비교, 거리 차 100m 이내가 95% 이상 (**제안**) | 좌표계 재확인 |
| 결측 보완 | 3,990건 중 주소로 좌표를 찾은 수 기록 | 못 찾은 건은 "위치 정보 없음"(8-4) |
| 겹침 | 같은 좌표에 가게가 과하게 몰린 곳 확인 (건물·시장 대표 좌표일 수 있음) | KNN에서 거리 0 처리 규칙 정하기 |

### 루프 D. 분류 검증 (G4)

| 점검 | 통과 기준 | 실패 시 |
|---|---|---|
| 미분류 비율 | "기타"·"미분류"가 다시 분류 후 10% 이하 (**제안**, 현재 13% 이상) | 키워드·카테고리 규칙 추가 |
| 분류 표본 | 무작위 100곳을 사람이 확인, 메인 메뉴 정답률 90% 이상 (**제안**) | 규칙 수정 |
| 프랜차이즈 | 주의표시 추정과 D9 매칭 결과 비교, 차이 나는 가게 확인 | 기준 확정 |
| 데이터 합치기 | D1+D2+D3 합친 뒤 같은 가게가 두 번 들어가지 않음 | 주소·상호 기준 중복 제거 |

### 루프 E. 계산 검증 (G5)

| 점검 | 통과 기준 | 실패 시 |
|---|---|---|
| 손계산 대조 | 표본 5곳(예: 동성로 초가식당, 군위군 연계식당 포함)을 엑셀로 직접 계산 → 코드 결과와 같음 | 코드 수정 |
| 분모 조건 | 비교 대상이 모두 폐업 가게이고, 자기 자신은 빠짐 | 코드 수정 |
| 최소 표본 | 비교 대상이 N곳(추정 5곳) 미만이면 "참고용" 표시 (7-3) | — |
| 분포 | 생존배수 분포를 구·군별로 그려 한 지역에 상위가 몰리지 않는지 확인 | 원인 확인 (데이터 문제인지, 실제 특성인지) |
| 극단값 | 상위 20곳·하위 20곳을 직접 확인 (인허가일이 이상하지 않은지) | 정제 규칙 보완 → 루프 B |
| 반경 | 비교 반경이 너무 넓은 가게(예: 3km 이상) 수 기록 | "참고용" 기준에 반영 |

### 루프 F. 결과 검증 (G6) — 공개 전 필수

| 점검 | 방법 | 통과 기준 |
|---|---|---|
| 백년가게 비교 (7-5) | D5를 주소로 매칭 → 백년가게 중 생존배수 상위 X%에 든 비율 계산 | 무작위 기준선(X%)보다 확실히 높음 |
| 안 맞는 백년가게 | 상위에 못 든 백년가게를 하나씩 원인 분류 (매칭 실패, 인허가일 문제, 주인 변경 등) | 원인이 데이터 문제면 루프 B·D로 |
| 민감도 (7-5) | k=5·10·20, ε 값 2~3개, 기간 제한 유무로 다시 계산 → 상위 100곳이 얼마나 겹치는지 | 겹침 70% 이상이면 안정 (**제안**) |
| 표본 확인 (회의록 10번) | 상위 가게 몇 곳을 지도·로드뷰·간판 등으로 실제 오래된 집인지 확인 | 명백히 틀린 가게 없음 |

판정: 백년가게 비교와 민감도가 기준을 못 넘으면 결과를 공개하지 않고(R2), 루프 E로 돌아가 산식 설정(k, ε, 기간 제한)을 조정합니다.
