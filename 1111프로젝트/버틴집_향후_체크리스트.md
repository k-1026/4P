## 0. 이미 정해진 것 (만들 때 지킬 기준)

- [x] 대상 사용자: 외지인(중점) + 동네 주민 (안건 1)
- [x] 푸는 문제: 광고 리뷰를 믿기 어렵고, 관광객용 맛집과 단골집이 섞여 있다 (안건 2)
- [x] '지금 영업 중인지' 확인은 이번 범위에서 제외 (안건 2)
- [x] 에이전트가 하는 약속: "살아남았다는 건 인정받았다는 것" — '맛이 검증됐다'는 말은 하지 않음 (안건 3)
- [x] 포함 가게: 다 넣는다 — 일반·휴게음식점, 주점, 프랜차이즈 (안건 4)
- [x] 비교 기준: 업종 + 주변 가게, 생존배수 + 보완 지표 (안건 6)

- [x] 검증: 백년가게와 비교 (안건 10)

## 1. 데이터 준비 — 담당: 이재훈

- [ ] 휴게음식점 데이터 추가 수집(카페·제과점·분식 일부) 후 일반음식점 97,575건과 합치기 (안건 4)
- [ ] 합친 뒤 전체 건수·구·군별 건수 다시 세기
- [ ] 업종 분류표 만들기 — 업종별 비교와 검색 필터에 사용 (안건 6)
- [ ] 인허가일자·폐업일자 결측치·이상치 처리 규칙 정하기
- [ ] 좌표 확인 및 보완 (KNN 계산과 지도 표시에 필요)
- [ ] 영업시간·메뉴 데이터 출처 확보 — 카카오 로컬 API·카카오맵 사용 가능 여부와 이용 약관 확인 (안건 9)
- [ ] 백년가게 목록 수집 — 검증용 (안건 10)
- [ ] 정리한 CSV를 GitHub에 올리고, 컬럼 설명(데이터 사전) 함께 작성

## 2. "오래 버텼다" 기준 — 같은 주인 기준 시도 (안건 5)

- [ ] 인허가 변경 정보(식약처)에서 대표자·상호 변경 이력을 뽑을 수 있는지 확인
- [ ] 가능하면: 같은 주인이 운영한 기간으로 영업연수 계산
- [ ] 안 되면: 인허가일 기준으로 계산하고, 상호·대표자 변경 이력을 '히스토리'로 남기기
- [ ] 정한 방식과 이유를 문서로 남기기

## 3. 생존배수 계산 (안건 6)

- [ ] **주변 가게 기준** 생존배수: KNN(K=10)으로 가까운 폐업 가게와 비교
- [ ] **업종 기준** 생존배수: 같은 업종 폐업 가게와 비교하는 방식 설계
- [ ] 보완 지표 ① 분모 평탄화: 분모에 최소 영업기간(ε)을 더해 극단치 완화 — ε 값 정하기
- [ ] 보완 지표 ② 중앙값 + 하한선: 평균 대신 중앙값, 30일 미만은 하한선으로 고정
- [ ] 비교 대상 폐업 가게의 기간 범위 정하기 (예: 최근 10년 안에 폐업한 가게만)
- [ ] 영업 중 가게가 낮게 계산되는 문제 보정 — 개업 연도가 비슷한 가게끼리 비교하는 방식 검토
- [ ] K 값 점검 — K=5·10·20으로 결과가 얼마나 바뀌는지 비교
- [ ] 반경이 너무 넓어지는 지역(예: 군위군 약 3km) 처리 기준 정하기
- [ ] 전체 가게의 생존배수를 미리 계산해 결과 표로 저장 (에이전트가 바로 꺼내 쓸 수 있게)

## 4. 결과 표시 단위 (안건 7)

- [ ] 생존배수에 붙일 단위 결정: 등수 / 퍼센트 / 등급
- [ ] 등급을 쓴다면 단계 수와 기준선 정하기 (예: 1~3단계)
- [ ] 등수를 쓴다면 범위 정하기 (구·군별, 업종별 등)

## 5. 에이전트 설계

- [ ] **에이전트가 하는 일 정의** — 사용자 질문을 받아 조건에 맞는 버틴집을 찾고, 왜 추천하는지 생존배수로 설명
- [ ] **페르소나별 대표 질문 모으기** (각 10개 이상)
  - 외지인 예: "동성로 근처에 오래된 국밥집 있어?", "대구 와서 꼭 가 볼 만한 노포 알려줘"
  - 주민 예: "우리 동네에서 제일 오래 버틴 집은?", "수성구 중국집 중에 주변보다 오래 버틴 곳"
- [ ] 질문에서 뽑아낼 조건 정하기: 지역(구·군·동·랜드마크), 업종, 정렬 기준, 개수
- [ ] **에이전트가 쓸 도구 목록** 정하기
  - 가게 검색 (지역·업종 조건)
  - 생존배수·순위 조회
  - 가게 상세 조회 (영업기간, 영업시간, 메뉴, 히스토리)
  - 길찾기 링크 만들기
- [ ] **답변 형식** 정하기 — 가게 카드 5개 항목 + 한 줄 추천 이유 (예: "주변 폐업 가게 평균보다 5배 오래 버텼어요")
- [ ] **말하면 안 되는 것** 정하기
  - 데이터에 없는 내용 지어내지 않기 (맛, 분위기, 가격 등)
  - "맛이 검증됐다" 같은 표현 금지 — 약속 문장 범위 안에서만 설명
  - 폐업했을 수 있는 가게라면 데이터 기준일(2026.10.28)을 함께 알려 주기
- [ ] 조건에 맞는 가게가 없을 때, 질문이 모호할 때의 응답 정하기
- [ ] 사용할 LLM과 호출 방식(도구 호출, 프롬프트 구조) 정하기
- [ ] 시스템 프롬프트 작성

- [ ] 외지인 페르소나 새로 만들기 — 중점 고객 (안건 1)

- [ ] 여정지도에서 나온 페인포인트를 5번 '대표 질문'에 반영

## 8. 검증·테스트

- [ ] **백년가게 비교**: 백년가게가 생존배수 상위에 얼마나 들어가는지 비율 계산 (안건 10)
- [ ] 겹치지 않는 백년가게는 이유 확인 (데이터 누락, 주인 변경 등) 후 계산 방식 보완
