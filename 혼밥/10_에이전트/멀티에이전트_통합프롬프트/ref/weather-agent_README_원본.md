# 날씨 에이전트 (대구)

## 처음 한 번

`api_key.txt`를 열어 안내 문구를 지우고, 공공데이터포털 API 키만 한 줄 넣고 저장한다.
이 파일은 다른 사람에게 보내거나 GitHub에 올리지 않는다.

## 실행

`run.bat`을 더블클릭한다.

## 동작

실행할 때마다 두 API를 조회한다. 기록을 쌓거나 자동 실행하지 않는다.

- 지금 값: 기상청 초단기실황 (대구 관측소가 있는 격자 90, 91)
- 전날 같은 시각 값: 기상청 지상(ASOS) 시간자료 (대구 관측소 143)

두 값 모두 대구 관측소 위치를 기준으로 한다. ASOS 값이 안 나오면 초단기실황의 23시간 전 정시 값을 대신 쓰고 화면에 "대체값"이라고 표시한다(23:00~00:14에는 없음). 전날 값이 없어도 추천은 그대로 나온다.

## 규칙 (지금 체감온도)

| 체감온도 | 결과 |
|---|---|
| 5도 이하 | 따뜻한 국물요리 |
| 5도 초과 10도 이하 | 따뜻한 요리 |
| 10도 초과 26도 미만 | 상관없음 |
| 26도 이상 | 차가운 요리 |

전날 체감온도는 참고로 보여줄 뿐 추천에는 쓰지 않는다.
전날 같은 시각(ASOS) 값이 있으면 "어제 같은 시각보다 N도 낮아요/높아요"를 함께 알려준다(결과 파일의 `comparison`). 대체값이면 비교하지 않는다.

## 다른 에이전트 말에 답하기

`weather.reply(report, 말한_에이전트, 가게_이름, 음식_종류)`를 부른다. `report`는 `main()`의 결과다.
음식 종류는 `따뜻한 국물`, `따뜻한 요리`, `차가운 요리`, `모름` 중 하나다.
결과의 `fits`는 맞음(`True`), 안 맞음(`False`), 판단 안 함(`None`)이다.
정해 둔 규칙으로만 답하며 자유로운 문장은 이해하지 못한다.

## 가게 날씨 점수

`weather.score(report, 음식_종류)`를 부른다. 결과는 `score`(0, 5, 10)와 `confirmed`다.

| 지금 체감온도 | 따뜻한 국물 | 따뜻한 요리 | 차가운 요리 |
|---|---|---|---|
| 5도 이하 | 10 | 5 | 0 |
| 5도 초과 10도 이하 | 10 | 10 | 0 |
| 10도 초과 26도 미만 | 5 | 5 | 5 |
| 26도 이상 | 0 | 5 | 10 |

음식 종류를 모르면 5점이고 `confirmed`가 `False`다.
조율자는 각 에이전트 점수에 사용자가 정한 퍼센트(합 100%)를 곱해 더한다. 날씨 에이전트는 합산하지 않는다.

## 반론하기

`weather.rebut(report, 말한_에이전트, 상대가_미는_가게, 그_음식_종류, 지금_1순위_가게, 그_음식_종류)`를 부른다.
결과의 `stance`는 `반대`, `동의`, `판단 안 함` 중 하나다.

| 경우 | 입장 |
|---|---|
| 상대 가게의 날씨 점수가 지금 1순위보다 낮음 | 반대 |
| 둘 다 0점 | 반대 |
| 상대 가게의 날씨 점수가 같거나 높음 | 동의 |
| 날씨 방향이 상관없음이거나 음식 종류를 모름 | 판단 안 함 |

반론 횟수(예: 1회) 제한은 조율자가 관리한다.

## 가중치와 순위

화면의 "가중치 정하고 순위 보기"에서 날씨·취향·가격의 퍼센트(합 100)를 정하면, 점수에 퍼센트를 곱해(10%면 0.1) 더한 순서로 가게를 보여준다.
날씨 점수는 음식 종류와 마지막 확인 날씨로 자동 계산하고, 취향·가격 점수(0~10)는 직접 적는다. 가게는 3곳까지다.
화면의 답하기·반론·순위는 버튼을 누를 때마다 날씨를 새로 가져온다. 가져오지 못하면 이전 값을 쓰지 않고 계산하지 않는다. 음식 종류가 "모름"인 가게는 순위에 "확인 안 됨"으로 표시한다.
계산은 `total.py`의 `rank()`가 하고, `python -m unittest test_total`로 시험한다.
