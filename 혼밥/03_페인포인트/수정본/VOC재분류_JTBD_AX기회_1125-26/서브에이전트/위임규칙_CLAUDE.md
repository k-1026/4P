# CLAUDE.md — 혼밥 프로젝트

## 위임 작업 규칙

이 폴더에서 업무를 맡기면 메인 세션이 지휘자가 된다.
지휘자는 질의를 분류하고, 작업자를 부르고, 채점을 맡기고, 사람 승인에서 멈춘다.
작업자·채점자는 서브에이전트라서 다른 서브에이전트를 부를 수 없다.
그래서 나누기·재작업·멈춤 판단은 모두 지휘자가 한다.

### 1. 질의 분류

| 질의에 이런 말이 있으면 | 작업 카드 | 작업자 | 루브릭 |
|---|---|---|---|
| 분류, 태그, VOC 재분류 | `ax/tasks/voc_tagging.md` | `voc-tagger` | `ax/rubrics/voc_tagging.md` |
| 잡 스토리, JTBD | `ax/tasks/jtbd.md` | `jtbd-writer` | `ax/rubrics/jtbd.md` |
| 출처, 인용 확인, 원문 대조 | `ax/tasks/source_check.md` | `source-checker` | `ax/rubrics/source_check.md` |

- 표에 맞는 줄이 없으면 실행하지 않는다.
  가장 가까운 카드 2개를 제시하고 묻는다.
- 카드나 루브릭 파일이 없으면 실행하지 않는다.
  없는 파일 이름을 알리고 멈춘다.
- 카드에 적힌 입력 파일이 없을 때도 실행하지 않는다.
  없는 파일 이름을 알리고 멈춘다.
- 질의가 카드와 다른 조건을 주면 질의를 따른다.
  다른 점은 계획에 "이번에만 바뀐 조건"으로 적는다.

### 2. 흐름 (항상 이 순서)

1. **계획만 제시한다.**
   읽을 파일, 만들 파일, 나누는 방식, 완료 기준, 사람이 확인할 지점을 보여 준다.
   승인 전에는 파일을 만들거나 고치지 않는다.
2. **승인 후 실행한다.**
   입력을 묶음으로 나눠 작업자를 병렬로 부른다.
   묶음 크기는 카드를 따르고, 카드에 없으면 100건 이하로 한다.
   작업자에게는 입력 경로, 행 범위, 카드 경로, 출력 경로를 넘긴다.
3. **채점을 맡긴다.**
   `review-grader`에 결과 파일과 루브릭 경로를 넘긴다.
   80점 미만인 묶음만 다시 작업자에게 보낸다.
   재작업은 묶음마다 최대 2번이고, 그래도 미달이면 사람에게 넘긴다.
4. **사람 확인에서 멈춘다.**
   무작위 10행(카드에 다른 수가 있으면 그 수)을 원문과 나란히 표로 보여 준다.
   완료 기준별 충족 여부를 표로 보고하고 멈춘다.
   사람이 승인하기 전에는 커밋하지 않는다.
5. **기록한다.**
   매 단계를 `ax/demo_log.md`에 덧붙인다 (아래 기록 형식).

### 3. 근거 규칙

- 고객 글 근거는 `voc_clean.csv`의 `voc_id`로만 단다.
  원문에 없는 id, 원문에 없는 상황·표현은 쓰지 않는다.
- 원문을 고쳐 쓰거나 요약할 때는 원문과 대조해 뜻이 같은지 확인한다.
- `대구거주`가 `모름`인 글은 대구 고객이라고 쓰지 않는다.
- 근거 등급(A·B·S·C·D)을 바꾸지 않는다.
  D등급 사례로 빈도·비율을 말하지 않는다.
- 공개용 결과물에는 원문을 길게 옮기지 않고 요약과 voc_id만 쓴다.

### 4. 위임하지 않는 일

- 정답이 사람 취향에만 있는 일 (서비스 이름 확정, 디자인 선택 등).
- 개인정보가 들어간 원본 처리.
- 팀 결정이 필요한 일 (페인포인트 추가·삭제, 점수 기준 변경).
  이런 질의는 선택지만 정리해 보여 주고 멈춘다.

### 5. 기록 형식 (`ax/demo_log.md`)

위임 한 건마다 아래 블록을 덧붙인다.
기존 내용은 지우거나 고치지 않는다.

```markdown
## YYYY-MM-DD · 작업 이름
- 위임한 업무 · 고른 이유 · 완료 기준 3개:
- 계획에서 사람이 고친 부분:
- 실행 중 개입 횟수와 이유:
- 채점 결과 (묶음별 점수, 재작업 횟수):
- 사람 검토 결과 (승인/반려)와 근거:
- 다음에 맡길 수 있는 범위 (한 줄):
```
