# 웹데이터 최신화·자동화 방안 (초안, 2026-11-24)

목표: 달서구 웹데이터를 한 번 만들고 끝내지 않고, **바뀐 것만 골라 다시 확인**해서 계속 최신으로 둔다. 사람이 하는 일은 "애매한 것 결정"과 "결과 승인"만 남긴다.

## 방안

### 1. 가게 목록 비교 (새 가게·사라진 가게만 골라내기)
- 상가정보 새 판이 나오면 상가업소번호로 지난 판과 비교: **새로 생긴 곳 / 없어진 곳 / 주소·상호 바뀐 곳**.
- 새로 생긴 곳만 수집 대기열에 넣고, 없어진 곳은 웹 파일에서 '폐업 의심'으로 표시.
- 보탤 수 있는 자료: 지방행정 인허가 자료(일반음식점 영업·폐업)로 폐업을 더 빨리 잡기. (사용 조건 확인 필요)

### 2. 다시 볼 날짜 정하기 (근거 수준별 주기)
- 확인됨: 6개월마다, 추정: 3개월마다, 업종 기준·모름: 수집이 될 때까지 대기열 앞쪽.
- 웹 파일에 `다음_확인일` 칸을 두고, 그 날이 지난 가게만 묶어서 수집.
- 주기는 사용자 결정.

### 3. 한 번에 돌리는 명령 (파이프라인)
`목록 비교 → 대기열 → 지시문 만들기 → Aside 수집 → 1차 판정 → 애매한 것만 Codex → Claude 검수 → 웹 파일 vN → 바뀐 목록`
- 단계마다 지금 있는 스크립트를 이어 붙인 것이라 새로 짤 것은 "이어 주는 스크립트" 하나.
- 사람이 보는 곳은 두 군데: ① 규칙에 없는 애매한 가게 묶음 질문, ② 웹 파일 새 판 승인.

### 4. 정해진 시간에 자동 실행
- Windows 작업 스케줄러 또는 Claude 예약 작업으로 매주(또는 매월) 3번 파이프라인 실행.
- Aside는 사용자 브라우저를 쓰므로 컴퓨터가 켜져 있어야 하고, 네이버가 막으면 다음 날 이어서 함(`run_all.sh`가 이미 이어 하기 됨).

### 5. 바뀐 것만 다시 판정 (메뉴 지문)
- 수집할 때 메뉴 글을 짧은 지문(해시)으로 저장. 다음 수집에서 지문이 같으면 판정을 건너뛰고 확인일만 바꿈.
- Codex 사용량을 크게 줄임.

### 6. 팀원에게 주는 형식 고정
- `웹데이터_달서구_vN_날짜.csv` + `바뀐목록_vN.csv`(새로 들어옴 / 판정 바뀜 / 빠짐) + 한 장 요약.
- 칸 이름은 v0에서 고정하고, 바꿀 때는 미리 알림 → 팀 웹 코드가 깨지지 않음.
- 웹이 JSON을 원하면 같은 스크립트에서 JSON도 같이 냄.

### 7. 품질 숫자를 매번 남기기
- 판마다: 모름 비율, 업종 기준 비율, 판정 바뀐 곳 수, 수집 실패 수.
- 숫자가 갑자기 바뀌면(예: 모름이 크게 늘면) 수집 방식이 깨졌다는 신호로 보고 멈춤.

### 8. 정답지로 정확도 재기
- 분기마다 무작위 50곳 전화·방문 확인 → 웹 판정과 비교 → "맞힌 비율" 기록.
- 업종 기준·추정 규칙이 실제로 맞는지 이걸로 확인하고 규칙을 고침(규칙 변경은 사용자 승인).

### 9. 이용자 제보 (웹을 연 뒤)
- 웹에 "1인분 돼요 / 안 돼요" 버튼 → 제보 표 → 같은 가게 제보 2건 이상이면 수집 대기열 앞쪽으로.
- 제보만으로 판정을 바꾸지는 않음(근거 수준 '제보'를 따로 둘지 결정 필요).
