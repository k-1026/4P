# 혼밥 챗봇 · 대구 (11월 27일 판)

- 작성일: 2026-11-24
- 우선 기회 O2 "1인분 + 취향 한 화면 거르기"의 첫 판이다.
- 범위는 `../밸류체인/analysis.md` "기한 안 범위" 표(2026-11-24 팀 확정)를 따른다.

## 여는 법

`honbap_chatbot.html`을 더블클릭해 브라우저에서 연다.
인터넷과 서버 없이도 동작한다.
식당 데이터가 파일 안에 들어 있어서, 이 파일 하나만 옮겨도 된다.

## 하는 일

1. 고객이 지역 · 음식 · 가격을 말하면 조건으로 알아듣는다.
   예: "성서 고기 1만2천원 이하", "동성로 국밥 만원", "추어탕 먹고 싶어"
2. 조건에 맞는 식당 가운데 2인분 이상인 곳은 빼고, 1인분이 확인된 곳부터 보여 준다.
3. 확인되지 않은 곳은 "1인분 확인 안 됨"으로 따로 보여 준다.
4. 뺀 2인분 이상 가게 수를 알려 주고, 원하면 따로 보여 준다.

## 대화 방식: 규칙 + Gemini 보조

- 규칙이 먼저 지역(구 · 동네 이름), 음식 종류, 가격, 메뉴 이름을 알아듣는다.
- 규칙이 아무 조건도 못 찾은 문장만 Gemini에게 보낸다.
- Gemini는 문장을 조건(JSON)으로 바꾸기만 한다.
  식당 이름과 1인분 판정은 항상 팀 데이터에서만 나온다.
- Gemini 키는 화면 오른쪽 위 "Gemini 설정"에서 사용자가 직접 넣는다.
  키가 없으면 규칙만으로 동작한다.
- 기본 모델은 `gemini-2.5-flash`이고, 설정 창에서 바꿀 수 있다.
- 키를 "이 브라우저에 저장"하면 그 브라우저에만 남는다.
  발표용 공용 노트북에서는 저장하지 않는다.

### 비용 막기

- 챗봇은 한 브라우저에서 하루 30회까지만 Gemini를 부른다.
  30회를 넘으면 Gemini 없이 규칙으로만 답하고, 다음 날 다시 30회가 된다.
- 남은 횟수는 오른쪽 위 버튼("Gemini 켜짐 · 오늘 n회 남음")과 설정 창에 보인다.
- 횟수를 바꾸려면 `template.html`의 `GEM_DAILY_LIMIT = 30` 숫자를 고치고 다시 만든다.
- 이 상한은 그 브라우저 안에서만 센다.
  키 자체를 보호하려면 Google 쪽 설정을 함께 한다.
  - 키를 만든 프로젝트에 결제 계정을 연결하지 않는다 (무료 등급이면 한도를 넘어도 요금 없이 거절만 된다).
  - Google Cloud Console에서 키의 API 제한을 "Generative Language API"만으로 둔다.
  - 결제 계정을 연결해야 한다면 Generative Language API 할당량의 하루 요청 수를 낮추고 예산 알림을 건다.

## 새로 모은 데이터 넣기

1. 이 폴더의 빈 양식 `수집양식_빈양식.csv`(29열, 팀 수집양식과 같음)를 복사해 채운다.
2. 파일 이름에 `수집양식`을 넣어 `data_src/`에 둔다.
   예: `data_src/수성구_수집양식_20261126.csv`
   파일은 여러 개여도 된다.
3. 아래 "다시 만들기" 명령을 실행한다.
   실행하면 맨 위에 "수집양식: 새 가게 n, 판정 바꾼 가게 n, 건너뛴 줄 n"이 나온다.

채우는 규칙:

- 꼭 채울 칸: `상호`, `구군`(비우면 `도로명주소`에서 찾음), `최소주문_판정`, `1인입장_판정`
- 있으면 좋은 칸: `대표메뉴`, `조건_적용범위`, `시간대제한`, `근거1_종류` · `근거1_출처` · `근거1_작성일`, `확인일`
- `수집ID`가 "예시"로 시작하는 줄과 `상호`가 빈 줄은 건너뛴다.
- 이미 챗봇에 있는 가게(같은 구 + 같은 상호)는 새 판정으로 바꾼다.
  이전 판정이 다르면 카드에 "이전 자료"로 남는다.

판정 칸 → 배지:

| 수집양식 값 | 배지 |
|---|---|
| `1인입장_판정` = 불가 | 2인분 이상 (혼자 입장 불가) |
| `최소주문_판정` = 2인분이상_확정 · 2인분이상_추정 | 2인분 이상 (`조건_적용범위`가 "일부 메뉴"면 일부 메뉴 2인 이상) |
| `최소주문_판정` = 1인분가능_확정, 또는 `1인입장_판정` = 가능 | 혼자 가능 확인 |
| `최소주문_판정` = 1인분가능_추정 | 2인분 조건 없음 (추정) |
| 미상 | 1인분 확인 안 됨 |

- 근거 원문은 `근거1_종류`가 메뉴표기일 때만 카드에 보인다.
  리뷰 · 블로그 원문은 보이지 않고 종류 · 출처 · 날짜만 보인다.
- 수집양식에는 가격 칸이 없어서, 새로 더한 가게는 가격 조건으로 거르지 않는다.

기존 자료를 늘릴 때:

- 달서구 다이닝코드 확인 CSV(`대구달서구_고깃집100곳_*`, `대구달서구_한식찜쭈꾸미등189곳_*`, `대구달서구_289곳_혼밥대응표시_*`)와 같은 이름 형식의 파일을 더 넣어도 모두 읽는다.
- 대구푸드 DB를 새로 받으면 `대구푸드_맛집DB_905곳.json`을 같은 이름으로 바꿔 넣는다.

## 다시 만들기

데이터나 화면을 고친 뒤 아래 명령으로 `honbap_chatbot.html`을 다시 만든다.
`honbap` 폴더에서 실행할 때:

```bash
python3 chatbot/build_data.py
```

`chatbot` 폴더 안에서 실행할 때:

```bash
python3 build_data.py
```

- 어느 폴더에서 실행해도 결과는 같다.
  스크립트가 자기 위치를 기준으로 `data_src/`를 읽고 결과 파일을 만든다.

- `template.html`: 화면과 대화 로직 (데이터 없음)
- `build_data.py`: `data_src/`를 합쳐 `restaurants.json`을 만들고, 템플릿에 넣어 `honbap_chatbot.html`을 만든다.
- `restaurants.js`: 템플릿을 따로 열어 볼 때만 쓰는 데이터 파일이다.

## 확인한 것과 못 한 것

- 브라우저에서 표본 데이터로 대화 흐름을 확인했다.
  "성서 고기 1만2천원 이하", "2인분 이상도 보여 줘", "처음부터", "추어탕 먹고 싶어", 못 알아듣는 문장을 시험했다.
- 전체 데이터가 들어간 `honbap_chatbot.html`은 미리보기 도구 제한으로 직접 열어 보지 못했다.
  팀이 브라우저에서 한 번 열어 확인한다.
- Gemini 보조는 키가 없어 실제 호출을 시험하지 못했다.
