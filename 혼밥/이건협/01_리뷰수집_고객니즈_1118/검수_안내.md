# 네이버 리뷰 판정 검수 안내 (1회차, 2026-11-19)

> 목적: Claude가 혼자 붙인 리뷰 판정이 사람 판단과 맞는지 확인한다. 맞으면 페르소나 재검토(`페르소나/버틴집_페르소나_재검토_네이버리뷰_2026-11-18.md`) 결과를 그대로 쓰고, 안 맞으면 판정 규칙을 고친다.
> 검수자: 팀원 **4명** (A · B · C · D). 네 사람 모두 **같은 60개**를 **서로 의논하지 않고** 따로 판정한다.

## 할 일 (한 사람당 약 20~30분)

1. 내 파일을 연다 — `검수표_A.csv` · `검수표_B.csv` · `검수표_C.csv` · `검수표_D.csv` 중 맡은 것 (엑셀로 열면 됨, 내용은 넷 다 같음)
2. 60개 리뷰의 **본문**을 읽고 두 칸을 채운다
   - **부정(예/아니오)**: 아래 "부정" 코드가 하나라도 있으면 예
   - **코드**: 해당하는 코드를 띄어쓰기로 여러 개 적는다. 없으면 비워 둔다
3. 헷갈리면 **메모**에 이유를 적는다
4. 저장해서 데이터 담당에게 보낸다
5. **`_Claude판정_검수끝나고열기.csv`는 다 끝날 때까지 열지 않는다** (답을 보면 검수가 의미 없음)

## 코드 (판정 규칙)

| 코드 | 뜻 | 부정? | 예 |
|---|---|---|---|
| **F** | 식사 자체 불만 — 뒤에 세부 글자를 붙인다: **m** 맛 · **y** 양 · **p** 가격 · **s** 응대(불친절) · **h** 위생 · **t** 늦게 나옴 | 예 | "직원이 너무 불친절" → `Fs` · "짜고 양이 적음" → `Fmy` |
| **H** | 헛걸음 — 휴무 · 품절 · 재료 소진 · 마감으로 못 먹음, 또는 "가려던 가게가 닫아서 여기 왔다" | 예 | "가려던 곳이 휴무라서 왔어요" |
| **Hi** | 영업 정보 불일치 — 네이버 정보(영업일 · 가격)와 실제가 다름 | 예 | "네이버엔 4,500원인데 키오스크는 6,500원" |
| **W** | 웨이팅 불만 · 포기 — 오래 기다려 힘들었음, 줄 때문에 못 먹음 | 예 | "매번 줄이 길어서 못 먹었는데" |
| **R-** | 리뷰 · 평점 보고 왔는데 실망 | 예 | "리뷰 많아서 가봤는데 그닥" |
| **E** | 기대 · 유명세 대비 실망 (방송 · 유명 · 소문 · 줄 서는 집인데 별로) | 예 | "방송 타고 바가지", "왜 줄 서는지 모르겠다" |
| **P-** | 주차 불편 | 예 | "주차할 데가 없어요" |
| Wm | 웨이팅 언급 (불만 아님) | 아니오 | "점심엔 웨이팅 있어요" |
| Wn | 대기 없이 들어감 | 아니오 | "웨이팅 없이 바로 입장" |
| R+ | 리뷰 · 평점 · 소문 보고 와서 만족 | 아니오 | "평점이 거짓말 안 하네요" |
| Rt | 리뷰를 믿을지에 대한 말 | 아니오 | "리뷰 믿기 어렵다고들 하는데" |
| Re | 리뷰 이벤트 (리뷰 쓰면 서비스) 언급 | 아니오 | "리뷰 이벤트 감튀 맛있어요" |
| Rd | "리뷰 이벤트 아님 · 대가 없이 쓴다" 해명 | 아니오 | "(리뷰 이벤트 아님)" |
| P+ | 주차 편함 | 아니오 | "주차장 넓어요" |
| T | 여행 · 출장 · 타지에서 옴 | 아니오 | "부산에서 놀러 왔는데" |

### 헷갈리기 쉬운 것
- **조금 아쉬움**도 불만이면 F로 적는다 ("쫄면은 조금 아쉬웠어요" → `Fm`). 칭찬이 대부분이어도 불만 문장이 있으면 적는다
- "배 별로 안 고팠는데 계속 들어가는 맛"처럼 **단어만 부정이고 뜻은 칭찬**이면 적지 않는다
- 사장님이 서비스로 음식을 줬다는 말은 Re가 아니다. **리뷰를 쓰는 조건**으로 받은 것만 Re
- 음식점 리뷰가 아니면(숙박 등) 메모에 "음식점 아님"

## 판정 기준 (데이터 담당이 계산)

```
python -I 00_스크립트/check_review_agreement.py
```

| 비교 | 통과 기준 |
|---|---|
| **4명의 다수결 ↔ Claude**, 부정(예/아니오) 일치율 | **80% 이상** |
| **4명의 다수결 ↔ Claude**, 주요 코드 일치율 (F · H · W · R- · E · P- 기준) | **70% 이상** |
| 참고: 사람끼리 6쌍의 부정 일치율 | 80%가 안 되는 쌍이 있으면 규칙 설명을 먼저 다듬는다 |

- 다수결 = 4명 중 **3명 이상**이 같은 답을 한 것 (2 대 2면 "아니오" · 코드 없음으로 봄)
- 한 사람씩 Claude와 비교한 일치율도 함께 나온다

- 통과하면 → 재검토 결과를 그대로 쓴다
- 통과하지 못하면 → 어긋난 리뷰를 같이 보고 규칙을 고친 뒤 358개를 다시 판정한다 (`voc_분류규칙.md`와 같은 방식)

## 표본 구성 (참고)

- Claude가 코드를 붙인 리뷰 40개 (식사 불만 · 헛걸음 · 웨이팅 · 리뷰 · 기대 · 주차에서 고루)
- 후보 단어가 있었지만 Claude가 "해당 없음"으로 둔 리뷰 10개
- 후보 단어가 없어서 Claude가 읽지 않은 리뷰 10개 (**빠뜨린 부정 리뷰가 있는지** 확인)
