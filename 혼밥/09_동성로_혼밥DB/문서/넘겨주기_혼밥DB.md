## 3. 표와 칸

| 칸 | 뜻 | 예 |

| 식당ID | 가게 번호(상가정보 번호) | MA0101... |
| 상호 | 가게 이름 | 현풍닭칼국수 동성로점 |
| 업종 | 업종 | 국수/칼국수 |
| 행정동 | 동 | 성내1동 |

| 위도, 경도 | 좌표 | 35.8656, 128.5969 |

| 마지막확인일 | 마지막으로 지도에서 확인한 날 | 2026-11-25 |
| 일인석 | 1인석·바 좌석: 있음 / 없음 / 비어 있음(모름) | 있음 |
| 일인석출처 | '있음'의 출처: 혼밥일기, 정보탭 | 혼밥일기 |

#### 혼밥 점수 (10점 만점, 11-26 결정) — `혼밥점수.py`

점수는 **DB에 저장하지 않습니다.** 앱이 위치 기반으로 고른 가게들(보통 20곳)의 식당ID를 넘기면 **그 가게들 안에서** 계산합니다.

- **후기점수 (최대 8):** 넘어온 가게들을 '혼밥하기 좋아요' 수로 줄 세워 **8칸**으로 나눕니다. 1등 칸 8점, 꼴찌 칸 1점입니다.
  20곳이면 아래처럼 나뉩니다.

| 순위 | 1~3 | 4~5 | 6~8 | 9~10 | 11~13 | 14~15 | 16~18 | 19~20 |
|---|---|---|---|---|---|---|---|---|
| 후기점수 | 8 | 7 | 6 | 5 | 4 | 3 | 2 | 1 |

- **일인석점수 (2):** 1인석·바 좌석이 혼밥일기나 네이버 정보 탭에서 '있음'이면 +2점, 없음·모름이면 0점.
- 수가 같으면 같은 순위, 같은 점수입니다. 가게가 20곳보다 적어도 같은 방식(식: 올림(8 × (가게수 − 순위 + 1) ÷ 가게수))으로 나누고, 1곳뿐이면 8점입니다.
- 같은 가게라도 **함께 넘어온 가게들에 따라 점수가 달라집니다**(그 자리에서의 순위이므로).
- 1인석은 출처마다 가장 최근 줄을 보고, 하나라도 '있음'이면 있음입니다. 같은 출처에서 나중에 '없음'이 오면 그 출처는 없음으로 바뀝니다.

```python
import sqlite3, 혼밥점수
con = sqlite3.connect("혼밥_동성로.db")
결과, 없는가게 = 혼밥점수.score(con, 위치기반_식당ID_20개)   # 혼밥점수 높은 순
# 결과 한 줄: {식당ID, 상호, 혼밥후기수, 순위, 가게수, 후기점수, 일인석, 일인석출처, 일인석점수, 혼밥점수}
# 없는가게: DB에 없는 ID(혼밥 조건을 못 넘었거나 동성로 밖) → 혼밥 점수 없음
```

명령 창 시험: `python -I 혼밥점수.py --위치 35.8690 128.5955` (그 자리에서 가까운 20곳)

### 식당
가게 기본 정보. 위 칸에 더해 `지도가게번호`(N=네이버, K=카카오 가게 번호), `처음넣은날`, `겹친ID`(같은 지도 가게라 합친 다른 목록 번호)가 있습니다.

### 근거
**한 가게에서 본 사실 하나가 한 줄**입니다. 지금은 가게마다 두 줄(일인메뉴, 혼밥후기수)이고, 1인석 정보가 오면 '1인석' 줄이 더해집니다.

| 항목 | 뜻 | 주요 칸 |
|---|---|---|
| 일인메뉴 | 1인분으로 시킬 수 있는 메뉴 | 메뉴명, 가격, 요지(화면 글 그대로), 판단(어떻게 1인분으로 봤는지) |
| 혼밥후기수 | 네이버 '혼밥하기 좋아요' 수 | 수, 본날 |
| 1인석 | 1인석·바 좌석 여부 | 수(1=있음, 0=없음), 출처(혼밥일기/정보탭), 요지, 본날 |

- `출처`: 메뉴글(네이버 메뉴 탭) / 메뉴사진 / 카카오메뉴 / 리뷰키워드 / 혼밥일기 / 정보탭(네이버 정보 탭)
- `상태`: **검토전**(AI가 화면에서 보고 적음, 사람은 아직 안 봄) / 사람확인(확인한 사람 이름이 있어야 함). **지금은 17곳의 1인 메뉴만 '사람확인'**(이재훈, 11-26)이고 나머지는 '검토전'입니다.
- 리뷰 글이나 리뷰 작성자는 **넣지 않았습니다.**
- 숫자가 바뀌면 덮어쓰지 않고 **새 줄**을 쌓습니다. 그래서 '혼밥가게' 보기는 가장 최근 줄을 보여 줍니다.

### 주요메뉴
가게의 중심 요리 최대 3개와 가격(`가격단위`: 단품 / 크기·세트 / 무게). 가격 에이전트가 메뉴 평균을 낼 때 쓸 수 있습니다.

### 검색기록
언제 어디서 찾아봤는지. 갱신할 때 다시 볼 곳을 고르는 데 씁니다.

### 설정
만든 날, 넣는 조건, 혼밥 후기 기준(5) 등.

## 4. 쓰는 법 (Python)

```python
import sqlite3
con = sqlite3.connect("혼밥_동성로.db")
con.row_factory = sqlite3.Row

# 혼밥 후기가 많은 순으로 10곳 (점수는 혼밥점수.py로)
for r in con.execute("SELECT 식당ID, 상호, 혼밥후기수, 일인석, 일인메뉴 FROM 혼밥가게 ORDER BY 혼밥후기수 DESC LIMIT 10"):
    print(dict(r))

# 한 가게의 근거 전부
for r in con.execute("SELECT 항목, 메뉴명, 가격, 수, 요지, 출처, 본날, 상태 FROM 근거 WHERE 식당ID=?", ("MA010120220803095305",)):
    print(dict(r))

# 예산 안의 1인 메뉴가 있는 곳 (예: 10,000원 이하)
q = "SELECT DISTINCT s.상호, g.메뉴명, g.가격 FROM 식당 s JOIN 근거 g USING(식당ID) WHERE g.항목='일인메뉴' AND g.가격<=?"
for r in con.execute(q, (10000,)):
    print(dict(r))
```

- DB 파일 하나만 있으면 됩니다. 설치할 것은 없습니다(파이썬 기본 `sqlite3`).
- 일부 1인 메뉴 줄은 메뉴명·가격 칸이 비어 있습니다. 메뉴 이름을 따로 뽑지 못한 경우이고, 원문은 `요지`에 그대로 있습니다.

## 5. 1인석·혼밥일기와 이어 붙이기 (혼밥일기 담당이 할 일)

1인석 정보는 **CSV 파일 하나**로 넘겨주면 됩니다. `1인석/` 폴더에 넣으면 DB를 만들 때마다 `근거` 표에 '1인석' 줄로 들어가고, 혼밥 점수에 +2점으로 반영됩니다.

- 파일 이름: `1인석/1인석_혼밥일기_YYYYMMDD.csv` (UTF-8). 빈 양식은 `1인석/양식_비어있음.csv`입니다.
- 칸

| 칸 | 넣을 값 | 예 |
|---|---|---|
| 식당ID | DB의 식당ID 그대로 | MA010120220800150732 |
| 1인석 | **있음** 또는 **없음** (1인석이나 바 좌석이 있으면 있음) | 있음 |
| 출처 | **혼밥일기** (다음 주 네이버 수집은 정보탭) | 혼밥일기 |
| 본날 | YYYY-MM-DD (일기를 쓴 날 또는 확인한 날) | 2026-11-30 |
| 요지 | 짧은 설명, 200자 안쪽. **작성자 이름·닉네임은 넣지 마세요** | 창가 1인석 4자리 |
| 확인자 | 사람이 직접 확인했으면 이름, 아니면 비움 | |

- 같은 가게를 여러 번 보내도 됩니다. 같은 출처에서는 **가장 최근 본날**이 쓰입니다.
- DB에 없는 식당ID, '있음/없음'이 아닌 값, 모르는 출처, 날짜 모양이 다른 줄은 **넣지 않고** DB를 만들 때 몇 줄 뺐는지 알려 줍니다(`설정` 표의 '1인석' 줄에도 남음).
- 다음 주에 네이버 정보 탭에서 모으는 좌석 정보도 같은 모양(출처=정보탭)으로 들어갑니다.
- 가게를 가리킬 때는 **식당ID**를 쓰면 됩니다. 이름은 지점 표기가 달라질 수 있습니다.

## 6. 앞으로 새로 고치는 방법 (혼밥 갱신 에이전트)

| 주기 | 할 일 | Aside(브라우저) 필요 | 지금 |
|---|---|---|---|
| 매주 | 인허가 자료에서 **새로 연 가게** → Aside로 1인분·혼밥 후기 확인 → 조건을 넘으면 DB에 넣음 | 예 | 만듦 |
| 매주 | 인허가 자료에서 **폐업한 가게** → DB에서 뺌 | 아니요 | 만듦 |
| 매주 | 1인분은 되는데 혼밥 후기가 5명이 안 되던 가게의 **후기 수 다시 보기** — 새 가게는 처음 본 뒤 2·4·8주에, 그 뒤와 기존 대기 가게는 매달. 한 번에 최대 30곳 | 예 | 만듦 (가짜 답으로만 시험) |
| — | 지난번 '지도에서 못 찾음'·'같은 가게인지 애매' 가게 다시 찾기 | 예 | 하지 않기로 함(11-26) |
| — | 혼밥 후기는 많은데 1인분이 확인 안 된 가게 다시 보기 | 예 | 하지 않기로 함(메뉴 갱신 때 볼 수 있음) |

'만듦'인 세 가지가 `갱신/매주_갱신.bat` 하나로 돌아갑니다(0 받기 → 1 비교 → 2 Aside 판정 → 2-2 후기 다시 보기 → 3 DB 반영). 후기가 모자란 새 가게는 판정 결과를 `갱신/후기대기_새가게.csv`에 남겨 두었다가, 다시 봐서 5명이 넘으면 DB에 넣습니다. 기존 대기 가게는 다시 본 수를 `갱신/누적_후기.csv`에 적고, DB를 만들 때 그 수로 다시 판정합니다(처음 수와 다시 본 수를 `근거`에 둘 다 남김). 지도에서 못 찾았거나 폐업·휴업 표시가 있던 가게는 더 보지 않습니다. 인증키는 `갱신/.env`에 넣고, 윈도우 작업 스케줄러 등록은 아직 하지 않았습니다. DB를 만들 때는 수집 폴더(`매칭도구/작업기록_20261125_중구동성로`)의 프로그램과 결과가 필요합니다.

## 7. 한계와 주의

- **대부분 AI가 지도 화면을 보고 적은 값이고, 사람이 확인한 것은 17곳뿐입니다.** '1인분'은 메뉴판에 한 사람 몫 메뉴가 있다는 뜻이고, 점심·저녁 등 **시간대별로 혼자 주문할 수 있는지는 확인하지 않았습니다**(예: '평일 3시 이후'처럼 시간 조건이 붙은 메뉴도 들어갈 수 있음).
- '혼밥하기 좋아요'는 네이버 리뷰 키워드 수입니다. 혼자 입장을 가게가 직접 보장한다는 뜻은 아닙니다.
- 성내3동이 11곳으로 적은 것은 그 동에 식당이 적고 대부분 조건(1인분·혼밥 후기 5명)을 못 넘었기 때문입니다.
- 같은 주소에 가게가 여럿인 곳(백화점·건물 안 27곳)은 서로 다른 가게입니다. 라쿵푸마라탕·라쿵푸훠궈 동성로점도 따로 둡니다(11-26 사용자 결정).
- 지도 링크와 가게 번호가 들어 있으므로 **공개 깃허브(4P)에는 올리지 말고 팀 안에서만** 주고받아 주세요.
