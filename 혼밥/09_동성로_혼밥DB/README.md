# 09_동성로_혼밥DB — 동성로 혼밥 DB · 자동 갱신 (2026-11-24 ~ 11-26)

> 만든 사람: 이재훈 (동성로 1,134곳 수집은 팀원 모두가 나눠서)

> 대구 **동성로(성내1~3동)** 에서 **1인분이 되고 혼자 가서 먹을 수 있는** 식당을 지도 화면으로 모아 DB를 만들고,
> 팀 공용 클라우드(Supabase)에 올려 **매주 저절로 새로 고쳐지게** 만든 기록입니다. 내가 맡은 에이전트는 **혼밥(갱신)** 입니다.

## 3. 전체 구조

```
[공공 식당 목록 1,134곳]
        │  Aside가 지도 화면을 보고 판정 (1인분 · 혼밥하기 좋아요 수)
        ▼
[수집 결과] ──> make_db.py ──> 혼밥 DB 391곳 (파일) ──> 올리기.py ──> Supabase honbap 구역
                                                                       │
                     앱(조율자) ── 읽기·혼밥 점수 함수(honbap_score) ───┘
                     다른 에이전트 ── 자기 구역(menu·price·taste·distance·weather)에 올림, restaurant_id로 이음

[매주 (클라우드, 컴퓨터 없이)]  인허가 API → 새 가게·폐업 비교 → 폐업은 바로 뺌, 새 가게는 '확인 대기'에 쌓음
[이 컴퓨터를 켤 때]            확인 대기를 Aside로 판정 → 조건을 넘으면 DB에 넣음   ← 아직 만들 것
```

## 5. 정한 것 (사용자·팀 결정)

- 수집 범위는 **동성로(성내1~3동)만**. 달서구·중구 나머지는 보류.
- 넣는 조건: 찾음 + 주요 요리 1인분 + 혼밥하기 좋아요 5명 이상. 소·중·대·세트뿐이면 N인분. 피자·치킨·술집 제외.
- 판정·추천은 DB에 저장하지 않음(근거만). 추천은 조율자가 함. 가격 계산은 가격 에이전트 몫.
- 혼밥 점수: 20곳 안 순위 8칸 + 1인석 2점(혼밥일기·네이버 정보 탭 중 하나라도 있으면).
- 매주 갱신: 새 가게만 Aside로 확인, 폐업은 인허가로 바로 뺌. 후기가 모자란 가게는 새 가게 2·4·8주, 나머지 매달 다시 봄(최대 30곳). 기존 '못 찾음' 가게는 다시 찾지 않음.
- 클라우드는 **Supabase(내 계정, 무료)**, 에이전트별 구역 + 팀원 멤버 초대 + '자기 구역만' 약속.
- 캡차는 사람이 직접 풂(프로그램은 풀거나 피해 가지 않음).

## 7. 한계와 주의

- 1인분·혼밥 후기 수는 **AI가 지도 화면을 보고 적은 값**입니다. 사람이 확인한 것은 17곳(1인 메뉴). 시간대별 주문 가능 여부는 보지 않았습니다.
- '혼밥하기 좋아요' 수는 11-25~26에 본 숫자입니다.
- 이 저장소는 **공개**라서 지도 링크·가게 번호·화면 글 원문·인증키는 올리지 않았습니다. 그 칸이 든 원본은 팀 안에서만 주고받습니다(팀원 묶음, Supabase).
