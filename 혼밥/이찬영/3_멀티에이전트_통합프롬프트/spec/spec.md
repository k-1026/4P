## 1. 목표

대구 동성로에서 혼자 점심을 먹을 사람이, 1인분이 되는지·얼마인지·얼마나 먼지·혼자 앉기 편한지를 한 화면에서 함께 보고 3곳 중 하나를 바로 고르게 한다.
(출처: `혼밥페인포인트_최종본.md` ① 1인분을 미리 거를 수 없다, ② 조건을 한 앱에서 함께 걸 수 없다, ③ 가 보기 전에는 알 수 없다)

| 성공 신호 | 재는 법 |
|---|---|
| 추천을 받은 사용자가 3곳 중 1곳 이상의 상세를 연다 | 결과 화면 → 상세 화면 이동 수 ÷ 결과 화면 수 |
| 요청부터 추천 3곳이 보일 때까지 사용자가 다른 앱을 열지 않는다 | 시험 사용자 관찰 (**확인 필요**: 몇 명, 언제) |

- 페인포인트 ④(눈치 보이는 자리)는 1인석 데이터가 모두 '모름'이라 v0 목표에서 뺐다.
  1인석이 채워지면 v1 목표에 더한다(4절 US4).

  휴대폰 브라우저로 연다.
  (출처: `혼밥_페르소나_v2.md`, `journey_map.md` 알아보기·둘러보기 단계)
- **보조 사용자:** 없음 (v0).

- **확인 필요:** 페르소나는 달서구 거주인데 데이터는 동성로(중구)다.
  "동성로에 일하러 온 사람(J5)"으로 볼지 팀이 정한다(9절 Q1).
- BM의 고객 세그먼트가 정해지면 이 절을 그것과 맞춘다(8절).

## 3. 서비스 구조 (자율형 멀티에이전트)

사용자는 한 문장으로 요청하고, 조율자가 에이전트들에게 일을 나눠 맡긴 뒤 결과를 모아 3곳을 답한다.
사용자는 에이전트를 직접 고르지 않는다.
(출처: `1126proto/00_전체구조.md` 1장·6장, `criteria.json`)

| 에이전트 | 화면에 드러나는 것 |
|---|---|
| 조율자 | 최종 3곳, 총점 `x.x / 10`, 이유 한두 문장, "다만 …" |
| 거리 | 도보 N분 |
| 예산 | 1인 N원 |
| 혼밥편의 | 혼밥후기 N명 · 1인석 있음/모름 |
| 날씨 | 오늘 체감온도와 음식 방향 한 줄 |
| 취향기록 | 혼밥일기가 있을 때만 "지난번 ○○" 한 줄 |
| 메뉴 | 1인 메뉴 이름·가격 (점수 없음) |
| 검증 | 화면에 드러나지 않음. 반려되면 조율자가 다시 계산 |

## 4. 기능 — 유저 스토리와 인수 조건

`spec/scenario.md`가 생기면 이 절을 그 파일의 스토리로 바꾼다.
스토리의 이유는 잡 스토리(J)와 페인포인트 번호에서 왔다.

### US1 [필수] 근처 3곳 받기 — 페인포인트 ①②, J5·J7

동성로에 점심 먹으러 나온 직장인으로서, 내 위치와 예산을 넣으면 1인분이 되는 근처 식당 3곳을 보고 싶다, 점심 먹을 곳을 못 찾아 편의점으로 때우지 않기 위해.

- [ ] 위치를 허용하고 "찾기"를 누를 때, 시스템은 1인분이 되는 가게 3곳을 순위·도보 분·1인 가격과 함께 보여 준다.
- [ ] 예산 10,000원을 넣을 때, 시스템은 1인 가격이 10,000원을 넘는 가게를 3곳에 넣지 않는다.
- [ ] 위치를 거부할 때, 시스템은 "동성로 중심에서 잰 거리예요"라는 문구와 함께 결과를 보여 준다.
- [ ] 조건에 맞는 가게가 3곳보다 적을 때, 시스템은 있는 만큼만 보여 주고 그 이유를 한 줄로 적는다.

### US2 [필수] 혼자 가도 되는지 근거 보기 — 페인포인트 ③, J9·J11

혼자 갈 곳을 정하려는 사람으로서, 가게마다 혼자 가도 되는지 근거를 보고 싶다, 따로 묻지 않고 갈지 정하기 위해.

- [ ] 추천 카드를 누를 때, 시스템은 1인 메뉴 이름·가격, 혼밥후기 수, 본날을 한 화면에 보여 준다.
- [ ] 근거가 AI가 지도 화면에서 읽은 값일 때, 시스템은 그 옆에 "AI 확인 · 사람 확인 전" 라벨을 붙인다.
- [ ] 1인석 정보가 없을 때, 시스템은 "1인석 정보 없음"이라고 쓰고 있음/없음을 짐작해 쓰지 않는다.

### US3 [필수] 추천 이유 보기 — 페인포인트 ②, J6·J7

조건을 여러 개 걸고 고르는 사람으로서, 왜 이 순서인지 보고 싶다, 1위가 내 조건에 맞는지 믿고 고르기 위해.

- [ ] 결과 화면이 열릴 때, 시스템은 가게마다 총점 `x.x / 10`과 이유 한두 문장을 보여 준다.
- [ ] 이유 문장 옆에, 시스템은 "AI 추천" 라벨을 붙인다.
- [ ] "시간이 없어요"를 고를 때, 시스템은 거리 비중을 높인 순위를 보여 주고 1위가 바뀌면 그 사실을 한 줄로 적는다.
- [ ] 한 에이전트가 실패할 때(예: 날씨를 못 가져옴), 시스템은 그 항목을 빼고 계산했다고 결과 화면에 적는다.

### US4 [나중] 1인석 있는 곳 먼저 — 페인포인트 ④, J8·J14

혼자 앉을 자리가 신경 쓰이는 사람으로서, 1인석·바 좌석이 있는 곳을 먼저 보고 싶다, 눈치 보지 않고 앉기 위해.

- [ ] 1인석이 '있음'인 가게가 후보에 있을 때, 시스템은 그 카드에 "1인석"과 출처·본날을 보여 준다.
- 데이터 조건: 1인석 값이 391곳 중 0곳이라 지금은 확인할 수 없다(`01_필요데이터_수정사항.md` 1.2).

### US5 [나중] 다녀온 뒤 기록 — 페인포인트 ③, J10·J12

다녀온 사람으로서, 1인분이 됐는지·1인석이 있었는지 남기고 싶다, 다음 추천이 내 기록을 반영하도록.

- [ ] 상세 화면에서 "다녀왔어요"를 누를 때, 시스템은 1인분 됨/안 됨, 1인석 있음/없음, 별점(1~5) 세 칸을 보여 준다.
- 데이터 조건: 저장 위치는 Supabase `taste.solo_seats`와 혼밥일기 표다(**확인 필요**: 일기 표 이름).

## 6. 완료 기준

4절의 필수 인수 조건(US1~US3)이 모두 예일 때 v0 완료다.
아래는 그중 테스트에서 먼저 보는 것과, 스토리에 묶이지 않는 기준이다.

- [ ] 위치를 허용하고 "찾기"를 누를 때, 시스템은 30초 안에 가게 3곳을 보여 준다. (US1, **확인 필요**: 30초)
- [ ] 폭 375px 화면에서 결과 화면을 열 때, 시스템은 가로 스크롤 없이 카드 3개의 이름·도보 분·1인 가격을 보여 준다. (US1)
- [ ] 예산 상한을 넘는 가게가 후보에 있을 때, 시스템은 그 가게를 3곳에 넣지 않는다. (US1)
- [ ] 1인 가격이 없는 가게가 3곳에 들 때, 시스템은 가격 자리에 "가격 모름"을 쓴다. (US1·US2, D13)
- [ ] 근거가 '검토전'일 때, 시스템은 "AI 확인 · 사람 확인 전" 라벨을 붙인다. (US2)
- [ ] 결과 화면에서, 시스템은 이유 문장마다 "AI 추천" 라벨을 붙인다. (US3)
- [ ] 날씨를 가져오지 못할 때, 시스템은 날씨를 빼고 계산했다고 적고 나머지 결과를 보여 준다. (US3)
- [ ] `python3 test_scoring.py`를 돌릴 때, 시스템은 실패 0개를 낸다. (전체)

## 7. 웹페이지 주소로 유저 플로우 만들기

화면이 만들어지면 그 웹페이지 주소를 넣어 `spec/userflow.md`(Mermaid 순서도)와 `spec/ia.md`(사이트맵 + 스토리 ↔ 화면 대응표)를 만든다.
주소가 없을 때는 4절 스토리와 7.2 화면 후보로 "계획 플로우"를 먼저 만들고, 주소가 생기면 "실제 플로우"로 다시 만들어 둘을 비교한다.

### 7.1 입력

| 입력 | 값 | 비고 |
|---|---|---|
| 웹페이지 주소 | `{{WEB_URL}}` | 예: `http://localhost:8000/`. 로그인이 필요한 주소는 받지 않는다 |
| 기준 문서 | 이 파일 (`spec/spec.md`) | 4절 필수 스토리, 7.2 화면 목록 |
| 시험 조건 | 위치 허용 / 거부, 예산 10,000원, "시간이 없어요" | 각 조건으로 한 번씩 지나간다 |

### 7.2 화면 목록 (후보, 팀이 확정)

화면 이름은 이 목록만 쓴다.
웹페이지에서 목록에 없는 화면을 만나면 새 이름을 만들지 않고 9절에 질문으로 남긴다.

| 화면 | 하는 일 | 스토리 |
|---|---|---|
| 홈·요청 | 위치 허용, 예산·"시간이 없어요" 고르기, 한 문장 요청 | US1·US3 |
| 진행 | 에이전트가 일하는 동안 기다리는 화면 | US3 (**확인 필요**: 단계 표시 여부) |
| 추천 결과 | 3곳 카드, 총점·이유·라벨 | US1·US3 |
| 가게 상세 | 1인 메뉴·가격·혼밥후기·본날·1인석 | US2·US4 |
| 결과 없음 | 조건에 맞는 곳이 없을 때 조건 바꾸기 안내 | US1 |
| 다녀왔어요 [나중] | 1인분·1인석·별점 기록 | US5 |

### 7.3 절차

1. 웹페이지 주소를 브라우저로 열고, 7.1 시험 조건마다 시작 화면에서 끝 화면(가게 상세)까지 지나간다.
   지나간 화면, 누른 것, 갈림길(예/아니오)을 적는다.
2. 화면마다 7.2 목록의 이름을 붙인다.
   맞는 이름이 없으면 "목록 밖 화면"으로 적는다.
3. `spec/userflow.md`에 Mermaid `flowchart`를 쓴다.
   시작·끝은 둥근 상자, 화면은 사각형, 분기는 마름모, 화살표에는 사용자 행동 라벨을 단다.
   주 경로 하나와 6절 완료 기준의 예외 경로 2개 이상(위치 거부, 결과 없음, 날씨 실패, 가격 모름 중)을 넣는다.
4. `spec/ia.md`에 사이트맵(들여쓰기 목록, 깊이 3 이내)과 스토리 ↔ 화면 대응표를 쓴다.
   화면이 없는 필수 스토리, 스토리가 없는 화면을 표 아래에 따로 적는다.
5. 웹페이지에서 본 것과 이 파일이 다르면 고치지 않고 "차이" 목록으로 남긴다.
   이 파일을 고칠지는 팀이 정한다.

### 7.4 지킬 것
