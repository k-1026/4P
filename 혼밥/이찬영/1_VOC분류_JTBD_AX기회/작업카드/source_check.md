# 작업 카드 — 원문 대조

## 목적

문서에 달린 voc_id · 인용 · 요약이 `voc_clean.csv` 원문과 맞는지 확인한다.
대상 문서는 고치지 않고, 대조 결과와 고칠 안만 만든다.

## 입력

- 대상 문서: 질의에서 받는다.
  질의에 없으면 `ax/jtbd.md`.
- 원문: `voc_clean.csv`

## 작업자 · 루브릭

- 작업자: `source-checker`
- 루브릭: `ax/rubrics/source_check.md`

## 판정 값 (이 네 개만 쓴다)

| 판정 | 뜻 |
|---|---|
| 일치 | 문서 주장이 원문 내용과 같다 |
| 과장 | 원문과 방향은 같지만 원문에 없는 말(시간·장소·감정·결과)이 더해졌다 |
| 원문에 없음 | voc_id는 있지만 원문에 그런 내용이 없다 |
| id 없음 | `voc_clean.csv`에 그 voc_id가 없다 |

- 대구거주 표기: 문서가 대구 고객이라고 했는데 원문 `대구거주`가 `모름`이면 `틀림`, 아니면 `맞음`.
  문서가 거주를 말하지 않았으면 `해당없음`.

## 나누기

- 대상 문서의 `##` 절 하나 = 묶음 하나.
- 절이 4개보다 많으면 이웃한 절을 묶어 4묶음 이하로 만든다.
- 출력: `ax/work/source_check/batch_NN.md`
- `source-checker`를 병렬로 부른다.

## 출력

- 합본: `ax/demo/source_check_report.md`
- 합본 맨 위에 판정별 개수와 대구거주 `틀림` 개수를 적는다.

## 완료 기준

1. 대상 범위에서 voc_id가 달린 주장을 빠짐없이 뽑았다.
2. 주장마다 판정이 하나다.
3. 일치가 아닌 곳마다 원문에 맞춘 고칠 안이 있다.
4. 대구거주 표기를 모두 확인했다.

## 사람 확인 지점

- 무작위 10개 주장을 원문과 나란히 보여 준다.
- `원문에 없음` · `id 없음` 판정은 전부 보여 준다.

## 하지 말 것

- 대상 문서를 고치지 않는다.
  고칠지는 사람이 정한다.
- 원문을 길게 옮기지 않는다 (요지 30자 이내).
