# 계획 플로우와 실제 플로우, 무엇이 달라졌나

- 작성일: 2026-11-26
- 작성: 이찬영 (Claude Code로 정리)
- 비교한 것: `spec/spec.md`로 그린 **계획 플로우 v0** ↔ 웹페이지 <https://honbap-bapchingu.vercel.app> 를 직접 지나가며 그린 **실제 플로우 v1**
- 자세한 순서도: `spec/userflow.md` (1절 실제 · 부록 계획), 사이트맵: `spec/ia.md`

## 1. 한 줄 요약

계획은 "한 화면에서 조건 걸기 → 기다리기 → 결과 → 상세" 네 단계였다.
실제 앱은 **채팅으로 하나씩 묻고, 상의 과정을 다 보여 주고, 마지막 결정에 사용자를 끌어들이는** 구조다.

## 2. 어떻게 확인했나

- 날짜: 2026-11-26
- 환경: Claude 내장 브라우저, 폭 375px(휴대폰 크기)
- 시험 조건: 중요 순위 거리 > 자리 > 가격 > 날씨 > 새로움, 업종 한식, 예산 1만 원 이하, 위치 허용 안 함
- 지나간 길: 중요 순위 → 업종 → 예산 → 위치 시트 → 상의 ①~⑤ → 최종 답 3곳 + 검증 8/8.
  지도 → 가게 상세 → 혼밥일기·마이 탭도 열어 봤다.
- 한계: 상의 마지막 갈림길에서 "아니요"를 누르려다 "네, 점수를 높일게요"가 눌렸다.
  그래서 1순위가 바뀐 쪽 결과만 봤다.

## 3. 흐름이 달라진 곳

| 번호 | 단계 | 계획 (v0) | 실제 앱 (v1) |
|---|---|---|---|
| C1 | 조건 넣기 | 홈 한 화면에서 예산·"시간이 없어요"를 고르고 한 문장으로 요청 | 채팅이 차례로 물음: 중요 순위 5개(날씨·자리·새로움·가격·거리) → 업종 → 예산 → "추천 시작". 업종 질문은 계획에 없었음 |
| C1 | "시간이 없어요" | 선택지로 있음 (거리 비중을 높임) | 없음. 중요 순위로 대신함 |
| C2 | 가중치 | `criteria.json` 고정 열(혼밥 35·거리 20·예산 20·취향 15·날씨 10) + 혼밥 MBTI 배수 | 사용자가 고른 순위대로 33·27·20·13·7% |
| – | 진행 | 기다리는 화면 (단계를 보여 줄지 미정) | 상의 ① 첫 의견 ② 후보 고르기 ③ 탈락 확인 ④ 1차 점수 ⑤ 상의가 채팅에 다 나옴. 후보 20곳 카드와 1차 점수표까지 공개 |
| C3 | 상의 | 1·2위 차이 0.5 이하일 때만 열림. **점수는 바뀌지 않음** | 반론이 나오면 "점수를 높일까요?"를 사용자에게 물음. "네"를 고르면 점수가 바뀜 (6.13 → 8.8점) |
| C4 | 총점 표기 | `x.x / 10` (소수 첫째 자리) | `7.80점`, `6.13점` (소수 둘째 자리) |
| C5 | 검증 | 화면에 안 보임 | 최종 답 아래 "검증 승인 · 규칙 8가지 중 8가지 통과" |
| C6 | 가게 상세로 가는 길 | 추천 카드를 누름 | 확인한 길은 **지도 탭 목록**에서 누르기. 추천 카드에서 들어가는지는 확인 못 함 |
| – | 끝 | "이 가게로 가기" | "길찾기 (카카오맵)", 찜하기, 오늘 방문 기록하기 |
| C7 | 다녀온 뒤 | [나중] 1인분 됨/안 됨, 1인석, 별점 세 칸 | 이미 있음: 혼밥일기(사진 1장 이상 필수), 모두·이웃 공유, 혼밥 레벨. 1인분·1인석을 묻는 칸은 확인 못 함 |

## 4. 계획에 없던 화면

| 화면 | 하는 일 | 비고 |
|---|---|---|
| 위치 정보 시트 | 위치 허용 / 허용 안 함 | 계획에서는 분기(마름모)였는데 실제로는 별도 시트 |
| 지도 탭 | 지도 + 가까운 순 가게 목록 (혼밥 좋아요 수·대표 메뉴·가격·거리) | 가게 상세로 들어가는 입구 |
| 마이 탭 | 혼밥 레벨, 찜한 가게 | 이 화면에 맞는 스토리가 spec에 없음 |

## 5. 계획대로인 곳 (C8)

- 위치를 거부하면 "동성로 중심에서 잰 거리예요"가 나온다 (US1).
- 추천 이유 옆에 "AI 추천" 라벨이 붙는다 (US3).
- 가게 상세에 "AI가 지도 메뉴 화면을 보고 적은 값 (사람 확인 전)"이 나온다 (US2).
- 1인석은 짐작하지 않고 "좌석 모름", "1인석·좌석 정보는 아직 모으는 중이에요"로 보여 준다 (US2).
- 1km 안 가까운 20곳으로 후보를 고른다.
- 혼밥 점수는 혼밥팀 최종본 규칙(후보 안 혼밥 후기 순위 8칸 + 1인석 2점)을 쓴다.
- 예산 1만 원을 넘는 가게는 최종 3곳에 없었다.

## 6. 아직 비교하지 못한 곳

| 경로 | 계획 | 실제 | 다음에 할 일 |
|---|---|---|---|
| 조건에 맞는 가게가 0곳 | "결과 없음" 화면 → 조건 바꾸기 | 확인 못 함 | 예산 8천 원 이하 + 드문 업종으로 시험 |
| 에이전트 하나가 실패 | 빠진 항목을 빼고 계산했다고 알림 | 확인 못 함 (이번에는 "모두 준비됐어요") | 날씨 API를 막은 상태로 시험하거나 개발 담당에게 확인 |
| 상의에서 "아니요, 그대로 둘게요" | – | 버튼만 확인 | 다시 지나가며 1순위가 유지되는지 확인 |
| 추천 카드 → 가게 상세 | 주 경로 | 확인 못 함 | 최종 답 카드를 눌러 확인 |

## 7. 팀이 정할 것

선택지만 정리했다.
고르는 것은 팀이 한다.

| 번호 | 정할 것 | 선택지 | 왜 중요한가 |
|---|---|---|---|
| ① | **상의에서 사용자가 점수를 바꿀 수 있게 할지** (C3) | 가. 앱처럼 바꿀 수 있게 하고 `criteria.json`을 고친다 · 나. 규칙대로 확실도(confidence)만 바꾸고 앱을 고친다 · 다. 점수는 그대로 두고 "사용자가 고른 곳"을 따로 표시한다 | `criteria.json`의 `debate.can_change_score: false`와 앱 동작이 정면으로 어긋난다. 검증 에이전트의 총점 계산 점검(R6)과도 엇갈릴 수 있다 |
| ② | 가중치 방식 (C1·C2) | 가. 중요 순위 방식으로 통일 · 나. 중요 순위 + 혼밥 MBTI 배수 · 다. 기존 고정 열 + "시간이 없어요" | `00_전체구조.md` 5장, `criteria.json` `weights`를 어느 쪽으로 맞출지 정해야 한다 |
| ③ | 총점 표기 (C4) | 가. 소수 첫째 자리로 맞춤 · 나. 소수 둘째 자리로 규칙을 바꿈 | spec 완료 기준과 검증 R1이 소수 첫째 자리 기준이다 |
| ④ | 새 화면을 spec에 넣을지 | 가. 위치 시트·지도·마이를 모두 화면 목록에 넣음 · 나. 지도만 넣음 · 다. 넣지 않음 | 유저 플로우·IA의 화면 이름이 spec 7.2 목록을 따른다 |
| ⑤ | 마이 탭(혼밥 레벨·찜)에 스토리를 둘지 | 가. 스토리를 새로 씀 · 나. [나중]으로 둠 | 지금은 스토리가 없는 화면이다 |
