# 데이터 준비 — 코드 단계 설명서 (v2 초안)

- 바꾼 날: 2026-11-27 (팀 결정 전 예측본)
- 이전: `prompts/menu.md` (메뉴 에이전트 시스템 프롬프트)
- 지금: 에이전트가 아니다.
  `prepare.py`가 추천 요청이 오기 **전에** 가게마다 값을 미리 계산해 둔다.

## 1. 만드는 값

| 값 | 계산 | 쓰는 곳 |
|---|---|---|
| `price` | `data/메뉴.json` 1인 메뉴 가격의 중앙값, 사사오입. 없으면 `null` | 예산 거르기·예산 점수 |
| `price_confidence` | 사람확인 근거 high · 검토전 mid · 가격 없음 low | 예산 점수 확실도, 검증 R7 |
| `kind` | 대표 메뉴 낱말 규칙 → 업종 대응표 (`../업종_음식종류_대응표_초안.md`) | 취향기록 |
| `kind_source` | "메뉴 낱말" 또는 "업종" | 확인용 |
| `weather_type` | 차가운 낱말 → 국물 낱말 → 종류 기본값 | 날씨 |
| `soup` | 대표 메뉴에 국물 낱말이 있는지 | 참고 |

## 2. 메뉴 에이전트가 하던 일은 어디로 갔나

| 메뉴 에이전트 일 | 지금 |
|---|---|
| 이름에 "2인"이 있는 메뉴 빼기 | DB를 만들 때 이미 1인분 근거만 넣음 (`data/메뉴.json`) |
| 1인 메뉴가 없는 가게 빼기 | 혼밥 DB 391곳은 모두 1인 메뉴가 있음 |
| `kind`, `weather_type`, `soup` 판단 | 낱말 규칙 + 업종 대응표 (코드) |
| `prices`, `price_min · median · max` 붙이기 | `price` 하나(중앙값)와 `prices` 목록 |
| `menu_from_main`, `solo_menu` | 쓰는 곳이 없어 만들지 않음 |

## 3. 돌리기

```bash
python3 -I v2_가격메뉴_코드화_초안/prepare.py
```

- 입력: `data/stores_동성로391.json`, `data/메뉴.json`
- 출력: `data/stores_prepared_v2.json` (391곳)
- 입력·출력 모두 팀 안에서만 쓰는 파일이다.
  공개 저장소에 올리지 않는다.
- 혼밥 DB가 매주 갱신되면 `data/build_from_final_db.py` 다음에 이 파일을 돌린다.
