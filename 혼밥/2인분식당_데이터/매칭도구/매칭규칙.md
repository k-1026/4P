# 가게 목록 매칭 규칙 (2026-11-21 정리)

두 가게 목록(예: 인허가 표본 ↔ 상권정보, 팀원 자료 ↔ 이쪽 자료)을 **상호 + 도로명주소**로 같은 가게끼리 맞추는 방법이다.
2인분 식당 작업에서 인허가 표본 4,435곳, 착한가격업소 506곳, 대구푸드 905곳을 상권정보(대구 2026-09)와 맞추며 정했다.

- 자동 부분: 같은 폴더의 `store_match.py` (A·B·C 단계와 손확인용 후보 목록까지)
- 사람이 하는 부분: 아래 4장 '손확인 순서' (E·G·D 판정, 지도 확인)
- 오늘 실제로 쓴 스크립트와 지도 확인 결과: `작업기록_20261121/`
- 가게를 맞춘 다음 2인분·혼밥 판정을 하는 도구는 아래 8장 (`judge_signals.py` → `compare_judgments.py` → `final_merge.py`)

## 1. 지키는 것

1. **원래 칸은 바꾸지 않는다.** 상호·주소 정리는 비교할 때만 하고, 파일에는 원본 상호를 그대로 둔다. 상대 쪽 상호는 `매칭_상호`·`상권_상호명`·`지도_상호`처럼 새 칸에 따로 적는다.
2. **억지로 잇지 않는다.** 확실하지 않으면 잇지 않고, 왜 안 이었는지 칸에 남긴다. 한쪽에만 있는 가게는 '짝 없음'으로 둔다.
3. **줄마다 어떻게 이었는지 남긴다.** `연결단계`(또는 `매칭_단계`)와, 손확인한 줄은 근거 칸을 꼭 채운다.
4. **고유번호가 있으면 번호로 먼저 맞춘다.** 인허가 `관리번호`, 상권정보 `상가업소번호`가 양쪽에 있으면 상호 비교 없이 그대로 잇는다. 단, 서로 독립적으로 찾아야 하는 검증 자료에는 번호를 미리 주지 않는다.

## 2. 주소·상호 정리 규칙 (비교할 때만)

도로명주소는 **"대구광역시 구 (읍·면) 도로명 건물번호"까지만** 남긴다.

| 원본에서 본 표기 | 정리 | 예 |
|---|---|---|
| 시도명 줄임 | '대구 ' → '대구광역시 ' | 대구 남구 명덕로12길 41 |
| 지하 | ' 지하 ' 지움 | 달구벌대로 지하 2100 ↔ 달구벌대로 2100 |
| 괄호·쉼표 뒤 (층, 동 이름) | 버림 | 동성로5길 22, 1층 (삼덕동) |
| 건물번호 뒤에 붙은 상호·층 | 버림 | 비슬로442길 3 미성김밥 |
| 붙여 쓴 건물번호 | 띄움 | 선원로34 → 선원로 34, 문화로47길6 → 문화로47길 6 |
| 도로명 안 띄어쓰기 | 붙임 | 비슬로 512길 58-5 → 비슬로512길 58-5 |
| 지번 주소(대구푸드) | 법정동 + 본번 + 부번으로 비교 | 남산동 2108-15 |

상호는 HTML 기호를 풀고(`&apos;` → `'`), 괄호 안을 지우고, 공백·기호를 지우고, 영문은 소문자로 바꿔 비교한다.
지점명은 붙인 것과 뗀 것을 둘 다 비교한다(상권정보는 상호명과 지점명이 칸이 따로다).

## 3. 연결 단계

| 단계 | 조건 | 업종 붙임 | 누가 |
|---|---|---|---|
| A_주소+상호 | 정리한 주소와 상호가 같음 | 붙임 | 자동 |
| B_주소+상호일부 | 주소가 같고 한 상호가 다른 상호 안에 들어 있음(2글자 이상). 예: 먹고을식당 ↔ 먹고을 | 붙임 | 자동 |
| C_상호+도로명 | 상호와 도로가 같고 건물번호만 다름, 그런 가게가 1곳뿐. 예: 명신반점 두류길 77 ↔ 79 | 붙임 | 자동 |
| E_손확인_같은가게 | 주소가 같고 맞춤법·띄어쓰기·지점명·법인명만 다름(맥시칸 ↔ 멕시칸, 83해치 ↔ 팔삼해치), 또는 상호의 고유한 부분이 같고 업종이 서로 맞음(형제칼국수 ↔ 형제식당(국수/칼국수)) | 붙임 | 사람 |
| E_지도확인 / 지도_이름바뀜 | 지도에서 그 주소의 음식점이 한 곳뿐이고, 상대 상호로 찾아도 그 가게가 나옴(김가네헛제사밥 ↔ 김가네철판닭갈비) | 붙임 | 사람+지도 |
| 지도_이전_상권연결 | 지도에서 같은 상호가 옆 번지 등 다른 주소에 있고, 그 주소의 상대 가게와 상호가 맞음 | 붙임 | 사람+지도 |
| G_판단불가 | 흔한 말만 같음('강변', '이가', '골목'), 또는 같은 상호가 같은 구 다른 주소에만 있음 | 안 붙임 | 사람 |
| D_다른가게 | 주소는 같은데 상호가 전혀 다름(출근길생고기 ↔ 퇴근길생고기) | 안 붙임 | 사람 |
| 지도_영업중_상권없음 | 지도에 그 주소에서 영업 중인데 상대 목록에 없음 | 안 붙임 | 지도 |
| 없음_행사·시장임시주소 | '동성로 28 일원(디저트 페스타)', '우보시장 일원' | 안 붙임 | 자동 |

## 4. 손확인 순서

1. `store_match.py`를 돌린다. A~C는 그대로 쓴다.
2. **D_주소만**: `매칭_같은주소_다른상호`의 가게들과 상호를 한 줄씩 본다.
   - 맞춤법·지점명만 다르면 E. 상호의 고유한 부분이 같으면 인허가 업태와 상대 업종이 맞는지 보고 E.
   - 흔한 말만 같거나 메뉴·영업 형태가 다르면 G. 전혀 다르면 D.
3. **없음**: 주소 표기를 먼저 의심한다(2장 표에 없는 새 표기가 있으면 규칙에 더한다). `매칭_같은상호_다른주소`가 있으면 체인 지점인지 확인한다. 체인이면 잇지 않는다.
4. **G·D·없음 중 꼭 필요한 곳만 지도 확인**: 카카오맵 → 없으면 네이버 지도. Aside에 맡길 때는 `작업기록_20261121/지도확인_Aside/aside_prompt_0.txt`의 지시문을 다시 쓴다.
   - 판정 값: 있음 / 이름바뀜 / 이전 / 없음_다른가게 / 없음 / 폐업표시
   - 지도에 보이는 것만 적고, 리뷰·작성자 정보는 모으지 않는다. 검색 사이에 2~3초 쉰다.
   - 네이버·카카오는 자동 수집을 약관으로 막는다. 수백 곳을 돌릴 때는 먼저 사용자에게 확인한다.
5. 손확인·지도 확인한 줄은 근거 칸(`손확인_근거`, `지도_메모`)과 확인일을 채운다.

## 5. 오늘 겪은 함정

- **같은 이름의 가게를 주소 없이 집으면 틀린다.** '강변식당', '이가식당', '웅이네'처럼 흔한 상호는 같은 구에 여러 곳이 있다. 손확인으로 이을 때 상대 가게는 반드시 **상호 + 주소**로 찾는다.
- **정규식 치환에 백슬래시를 셸로 넘기면 깨진다.** 스크립트는 파일로 쓰고, 셸 한 줄 명령으로 `\1` 같은 치환식을 고치지 않는다.
- **새로 뽑은 표기 기준을 기존 집계와 섞지 않는다.** 대구푸드 '2인 이상' 표기를 정규식으로 다시 뽑으면 16곳이 36곳이 됐다. 기존 집계 파일의 표시만 옮겼다.
- **상권정보는 빠진 가게가 많다.** 인허가 표본 중 358곳이 지도에서는 영업 중인데 상권정보(2026-09)에 없었다. 상권정보 업종으로만 만든 후보는 실제보다 적다.
- **지도 업종은 상권 소분류보다 거칠다.** '육류,고기'는 돼지·소를, '해물,생선'은 횟집과 구이·찜을 나누지 않는다. 지도 업종으로 정한 것은 칸을 따로 둔다(`지도기반_2인분후보`).

## 7. 팀원 자료와 합칠 때

- 팀원 자료에는 **상호와 도로명주소(건물번호까지)**를 꼭 적어 달라고 한다. 구·군 칸이 있으면 더 정확하다.
- 이쪽 번호(관리번호·상가업소번호)는 검증이 끝나기 전에는 주지 않는다(서로 독립적으로 찾기 위해).
- 합칠 때: 팀원 자료를 왼쪽, 이쪽 연결 파일(또는 상권정보)을 오른쪽에 넣고 `store_match.py`를 돌린 뒤 4장 순서로 손확인한다. 이쪽 연결 파일을 오른쪽으로 쓸 때는 `--r-name 상호 --r-addr 도로명주소 --r-gu 구군 --r-id 관리번호`로 칸 이름을 바꿔 준다.

예:
```powershell
python -I "C:\Users\Green\Desktop\팀프로젝트 - 혼밥\매칭도구\store_match.py" 팀원자료.csv "C:\Users\Green\Desktop\팀프로젝트 - 혼밥\원본자료\소상공인시장진흥공단_상가상권정보_대구_202609.csv" 결과.csv --l-name 상호 --l-addr 주소 --l-gu 구군
```
