## 핵심 논의

1. Claude가 폴더 구성과 파일 크기를 확인했다.
   - 큰 파일: `6_대구전체_음식점_영업기간/대구전체_일반음식점_WGS84.csv`(약 26MB), `대구전체_음식점_영업기간.zip`(약 23MB). 둘 다 GitHub 파일당 100MB 제한보다 작다.
   - zip 안의 파일 3개(html 4,446,163B / xlsx 15,465,063B / csv 26,146,650B)가 6번 폴더 파일들과 크기가 같았다. 그래서 중복으로 판단했다.
2. Claude가 두 가지를 물었고, 사용자가 답했다.
   - 올릴 위치: 개인 저장소(origin)와 팀 저장소(team) 중 **팀 저장소**를 골랐다.
   - 배치 방식: Claude가 추천한 "원본은 `data/raw`, 정리 문서는 `docs`"를 골랐다.
3. 처음에는 새 브랜치 `jaehoon/daegu-pay`를 만들었다. 그런데 fetch해 보니 팀 저장소에 이미 `이재훈` 브랜치가 있었다.
   - `team/이재훈`은 당시 `team/main`보다 커밋 하나("Add 1030실습 folder")만 뒤처져 있었고, 별도 작업은 없었다.
   - Claude는 "내 branch"가 이 브랜치라고 판단했다. 그래서 `jaehoon/daegu-pay`를 지우고 `이재훈` 브랜치에 올렸다. **이 결정은 Claude가 판단한 것이고, 사용자가 명시적으로 확인하지는 않았다.** 이후 사용자가 이의를 제기하지는 않았다.
4. `이재훈` 브랜치는 이전 커밋들("Delete package.json", "Delete README.md" 등)로 기존 파일이 모두 지워진 상태였다. 그래서 이번에 올린 자료만 이 브랜치에 있다.

- 올릴 곳은 팀 저장소(k-1026/4P)이다.
- 배치는 원본은 `data/raw`, 정리 문서는 `docs`로 나눈다.

## 보류·제외한 방안과 이유

- **`대구전체_음식점_영업기간.zip` 업로드 제외**: 6번 폴더와 같은 파일 3개(크기 일치)라서 뺐다.
- **새 브랜치 `jaehoon/daegu-pay` 사용 취소**: 사용자는 처음에 "팀 저장소에 새 브랜치"를 골랐다. 하지만 이미 `이재훈` 브랜치가 있어서 그쪽에 올리고, 새 브랜치는 로컬에서 지웠다(원격에는 푸시하지 않았다).
- **"폴더 그대로 통째로 복사"안 제외**: 사용자가 data/raw·docs로 나누는 방식을 골랐다.
- **로컬 main의 `과제.pdf` 삭제 변경**: 이번 작업과 관계가 없어 커밋하지 않았다.
