## 핵심 논의

### 1. 출발점: 사용자가 직접 겪은 문제 [사용자]
- 바이럴·인스타·유튜브 광고 음식점에 갔다가 맛이 없거나 후회한 적이 꽤 있음
- 음식점에 갔는데 문이 닫혀 있으면 스트레스를 받음
- 네이버 지도의 문제: 폐업 가게가 그대로 나옴, 영업시간이 틀림, 전화번호가 없음, 지도 위치가 간단하고 주변에 도착하면 안내가 꺼져서 가게를 찾기 어려움
- 대한민국 구석구석의 문제: 데이터는 많고 정리돼 있지만 10등까지만 보이고 나머지는 찾기 어려움

### 2. 타깃과 문제 정의
- [사용자] 타깃은 **"그 지역의 로컬 음식을 먹고 싶어하는 여행객"**
- [사용자] 방향: 로컬 사람들이 가는, 알려지지 않은 음식점 + 믿고 갈 수 있는 곳
- [AI 제안] "알려지지 않은 집"과 "믿을 수 있는 집"은 원래 충돌함(알려지지 않을수록 정보가 적음). 이 충돌을 푸는 것이 서비스의 존재 이유

### 3. 기존 서비스 조사 [AI 조사]
| 서비스 | 강점 | 한계 |
|---|---|---|
| 네이버 지도·플레이스 | 정보량, 사장님이 영업시간 직접 관리 | 사장님이 관리 안 하면 틀림, 영수증 리뷰가 건당 500~1,000원에 거래됨 |
| 대한민국 구석구석 | 공공 플랫폼, 회원 100만, 이동 데이터 반영 | 맛집차트 1위가 맥도날드라는 국회 지적(2026-09) |
| 카카오맵 | 이용자 많음 | 랭킹·리뷰가 마케팅 상품으로 판매됨 |
| 다이닝코드 | 블로그 분석으로 광고 필터링 | 블로그 글 없는 노포는 못 잡음 |
| 뽈레 | 광고 없는 미식가 리뷰 | 기준이 현지인이 아니라 미식가 |
| 캐치테이블·테이블링 | 실시간 예약·웨이팅 | 제휴 매장만 |
| 당근 | 위치 인증된 주민 정보 | 주민끼리만 봄 |
| 트리플 | 여행자 간 실시간 정보 | 정보원이 다른 여행자 |

- 공통점: 신뢰를 "방문했는가"로 증명하고, 인기도로 순위를 매김 → 알려진 곳이 계속 위에 남음

### 4. 사용자 요청: 객관적으로 봐 달라
- [사용자] "이제부터는 내 이야기에 무조건 긍정하지 말고 객관적으로 봐줘"
- AI가 그동안 과하게 긍정한 부분을 정리함: 범위가 계속 넓어짐, 공공데이터 한계(인허가일 ≠ 실제 업력, 폐업 신고 지연)를 가볍게 말함, 구석구석을 "고객"으로 본 것은 희망에 가까움, 공공데이터 수집 자동화는 누구나 할 수 있어서 경쟁 우위가 얇음

### 5. 과정 목표와 일정
- [사용자] "이 프로젝트에서 제일 중요한 건 AI와 코딩을 이용해서 자동화를 시키는 게 목표", "자동으로 돌아가는 AX 결과물을 가지고 발표하는 거야. 실행이 돼야 해"
- 커리큘럼 기준: 11/18 피칭, 12/2 AI 자동화 워크플로우 실습, 12/4 데모데이, 12/7~12/18 실전 AX 프로젝트(원래는 새 주제가 원칙이지만 운영진이 이어가도 된다고 함)
- 과정 도구: Supabase, Vercel, Gemini API(무료), Claude Code 예약 작업 또는 n8n

### 6. 팀 데이터 확인 (사용자 컴퓨터 `과제` 폴더)
- 정리 문서 00~11번, 인허가 CSV(대구 97,575건), 대구로페이·온누리 자료를 확인했어요.
- AI가 인허가 CSV를 직접 다시 집계한 결과:
  - 영업 중 29,277곳 중 **전화번호 없음 53.5%** (20년 이상 가게는 23.3%)
  - 최근 30일 신규 283건, 폐업 360건 → **하루 평균 약 18~21건 변동**. 인허가 API(15154916)가 일간 갱신이라 자동화 데모에서 변화가 보임
  - 20년 이상 영업 중 7,302곳, "지위승계 의심" 표시 3,865곳
  - 상호명에 대구10미 키워드가 있는 가게 790곳
  - 도로명에 '안지랑' 포함 영업 중 33곳(20년 이상 8곳), 중구 대신동 138곳(전화 없음 68.1%), 중구 동인동 270곳
- **정정:** AI가 앞에서 "인허가 데이터로 전화번호를 자동으로 채운다"고 했는데, 인허가 데이터에도 절반은 전화번호가 없어서 틀린 설명이었어요.
- [AI 판단] 팀이 쓰는 공공 근거(오래 버팀, 기관 인정, 대구다움)가 "현지인이 인정한 집"의 근거 역할을 할 수 있음. 과정 기간에 현지인 리뷰를 모으는 것보다 현실적

### 7. 판정 기준 확정 과정
- [사용자] "맞아 그래서 내가 나의 주제로 만들고 싶던 거야, 나의 기준으로"
- AI 초안: 4단계 (걸러내기 → 대구 음식 → 광고 아닌 근거 → 지금 갈 수 있는가)
- 사용자 선택 (질문 응답):
  - 대구 음식(대구10미 등): **가점 조건** (필수 아님)
  - 알려지지 않은 집: **판단 보류**
  - 근거 반영 방식: **점수로 순위**
- [AI 지적] 점수 순위는 "구석구석처럼 상위 10개만 보인다"는 비판과 충돌할 수 있음 → 인기도를 점수에 넣지 않고, 근거 내역을 공개하고, 필터 후 전체를 보여주는 원칙으로 해결

### 8. 배점 방법과 찜
- [사용자] "배점 쪽을 더 진행해 보자. 저거 말고도 방법은 없을까", "우리가 진행하는 곳 안에서 찜을 받는 것도 안 좋을까"
- [AI 제안] 배점 방법 5가지: 고정 배점 / 희소성 가중치 / 업력 백분위 / 사용자 선택형 / 평가 데이터로 학습
- 희소성 가중치 계산(근삿값, 최고 3): 백년가게 60곳 3.0, 구청 추천 272곳 2.3, 모범·구청 지정 368곳 2.1, 대구10미 835곳 1.7, 영업 20년 이상 7,302곳 0.7
  - 한계: 모범음식점처럼 일부 구에만 명단이 있으면 실제보다 드물게 잡힘 → 명단 있는 구 안에서만 계산
- [AI 의견] 찜의 문제: 찜은 검증이 아니라 관심, 유명한 곳이 더 유명해짐, 초기 숫자가 적어 흔들림, 조작 가능
- [AI 제안] 찜 대신 '다녀왔어요' 3단계 평가(추천/좋음/별로), 주민·여행객 평가 분리, 최소 인원(예: 5명), 1인 1가게 1회, 가게 근처 위치에서만 평가
- [AI 제안] **근거 점수(공공 기록만)와 방문 평가를 분리해서 표시.** 평가가 쌓이면 배점 검증에 사용

### 9. 네이버와의 차이
- [사용자] "그러면 네이버랑 뭐가 다르지. 명확한 내용이 있으면 좋겠어"
- [AI 의견] 방문 평가 자체는 네이버 영수증 리뷰와 거의 같아서 차별점이 아님. 차별점은 "무엇으로 순서를 매기느냐"
- 핵심 문장: **"네이버는 많이 찾는 집을 보여주고, 우리는 돈으로 살 수 없는 근거가 있는 집을 보여준다"**
- 예상 질문 "네이버가 필터 하나 추가하면 끝 아니냐": 기술적으로 가능함. 답은 네이버 수익 구조(플레이스 광고)와 구별 명단 수집·업력 보정 같은 지역 작업량. 기술적 진입장벽이 아님을 인정
- 네이버와 경쟁하지 않고, 가게 카드에서 네이버 길찾기로 연결

- [사용자] 내 주제로, 내 기준으로 만들고 싶다.

## 확정한 사항

- **타깃:** 대구의 로컬 음식을 먹고 싶은 여행객
- **페르소나 (사용자 "너무 좋다"):**
  - 메인 박지훈(29세, 서울 직장인, KTX 1박 2일, 여행 목적 절반 이상이 음식, 끼니 3~4번)
  - 보조 최영숙(54세, 대구 남구 30년 거주, 안지랑 단골, 방문 평가·영업 제보를 남기는 공급 측 참여자)
- **판정 기준 구조:** 1 걸러내기(영업 중, 전국 프랜차이즈 제외·대구 로컬 체인은 본점만, 축제 임시허가 제외) → 2 근거 점수(공공 기록만, 대구 음식은 가점) → 3 방문 평가(분리 표시) → 4 영업 상태(표시용)
- **대구 음식:** 가점 (필수 아님). 화면에 '대구 음식만 보기' 필터
- **알려지지 않은 집:** 판단 보류
- **순위:** 점수로 정렬, 단 인기도 지표는 점수에 넣지 않음
- **핵심 문장:** 돈으로 살 수 없는 근거
- **진행:** 같은 팀·같은 주제로 12/18까지
- **결과물:** 개인 기획서를 위 내용으로 공적인 말투로 다시 작성 (Claude Docs, 10개 장)

## 검토 중인 사항

모두 **[AI 제안]**이고 팀 논의가 필요해요.
- 희소성 가중치 + 업력 백분위로 근거 점수 계산 (사용자가 배점 방법을 최종 선택한 기록은 없음)
- 근거 점수와 방문 평가 분리 (사용자가 명시적으로 확정한 기록은 없지만 기획서에 반영됨)
- '다녀왔어요' 평가 방식, 최소 인원 5명, 위치 기반 평가
- MVP 지역 안지랑 곱창골목 (남구는 모범음식점 명단, 안지랑 명단 52곳, 인허가일자가 모두 있는 구)
- 위생등급·착한가격은 기준이 아니라 참고 정보로
- 도착 안내(입구 사진, 기준점 설명)는 확장 1순위
- BM: 사용자 무료, 가게에 노출 판매 안 함, 장기적으로 B2G·B2B 데이터 공급 (과정에서는 확장 계획 수준)

## 보류·제외한 방안과 이유

- **현지인 리뷰를 핵심 검증 수단으로** → 과정 기간에 의미 있는 규모로 모으기 어려움. 공공 근거로 대체하고 평가는 보조로
- **찜을 점수에 반영** → 관심이지 검증이 아니고, 인기 쏠림·조작 문제. '다녀왔어요' 평가로 대체
- **고정 배점(3·2·1점)** → 근거가 약함. 데이터 기반 배점 쪽으로
- **네이버·카카오 리뷰 크롤링** → 약관 문제, 판매할 데이터는 권리관계가 깨끗해야 함
- **대한민국 구석구석을 첫 고객으로 보는 시각** → 맥도날드 1위 문제는 프랜차이즈 제외만으로도 일부 해결되고, 초기 팀의 데이터를 공공이 살 가능성이 낮음. 문제의 존재 근거로만 사용
- **외국인 관광객 타깃** → 다국어 지원이 필요해 확장 대상으로
- **Streamlit·GitHub Actions** → 과정 도구(Supabase, Vercel, Gemini, 예약 작업·n8n)에 맞추기로
