## 1. 무엇을 하는 프로젝트인가

**광고 리뷰 대신 "얼마나 오래 버텼는가"로 음식점을 고르게 하는 서비스**입니다.

- 대구 음식점(일반음식점 · 휴게음식점 · 제과점) 전체의 인허가 개업일 · 폐업일을 공공데이터로 모읍니다.
- 가게마다 지금 **영업 중인지 폐업했는지** 판정합니다. 폐업 신고 없이 문 닫은 가게가 인허가에는 계속 "영업"으로 남기 때문입니다.
- 팀 페이지는 이 자료로 **생존배수**(그 가게의 영업 기간 ÷ 주변 같은 업태 폐업 가게들의 평균 영업 기간)를 계산해 보여 줍니다.

프로젝트는 처음에 "여행객 한 끼 추천"이었다가 2026-11-05에 "버틴집"으로 방향을 바꿨습니다.

## 4. 영업 / 폐업 판정 방법

확실한 것부터 단계별로 걸러, 사람이 봐야 하는 가게를 최소로 줄입니다.

| 단계 | 방법 | 판정 | 가게 수 |
|---|---|---|---:|
| 1 | 인허가에 폐업 신고가 있음 | 폐업 (확정) | 93,760 |
| 1 | 10/28 이후 새로 영업 신고 | 영업중 (확정) | 175 |
| 2 | 상가정보의 같은 건물에 비슷한 상호가 있음 | 영업중 (추정) | 28,849 |
| 3 | 카카오 검색: 상호 유사도 0.8 이상 + 100m 이내 | 영업중 (추정) | 4,249 |
| 3 | 카카오 검색: 결과 없음, 또는 후보 모두 유사도 0.5 미만 | 폐업 (추정) | 4,487 |
| 4 | 위에서 못 가린 가게 | 사람 확인 (미확인) | 1,546 |

**최종판정 = 조원 판정이 있으면 조원 판정, 없으면 자동 판정.** 4단계인데 아직 아무도 안 본 가게는 `미확인`입니다.

**사람 확인 1,546곳의 이유**

| 이유 | 곳 수 |
|---|---:|
| 상호가 비슷하지만 같은 가게인지 불확실 (유사도 0.5~0.8) | 708 |
| 같은 상호가 100m 넘게 떨어져 있음 (이전 · 다른 지점 가능) | 384 |
| 좌표 없음 | 207 |
| 위치 검색이 안 맞는 유형 (푸드트럭 · 고속도로 휴게소 · 백화점 안 매장) | 108 |
| 상호 · 주소가 바뀌어 상가정보와 다시 대조했는데 안 맞음 | 82 |
| 구내식당 · 장례식장 등 일반 검색에 안 나오는 유형 | 37 |
| 너무 흔한 상호 (식당 · 분식 등) | 20 |

**검증한 것**
- 표본 300곳에서 이 규칙과 Claude 에이전트의 판정이 295곳(98%) 같았습니다. 다른 5곳은 괄호 속 영어 이름 때문이었고 규칙 쪽이 맞았습니다.
- 인허가 자료는 API · 전국 파일 · 대구 지역별 파일 세 가지로 받아 서로 한 칸도 다르지 않음을 확인했습니다 (11/11).
- 빈 폴더에서 재료만으로 처음부터 다시 만들어, 아카이브 133,039개 파일까지 모두 같게 나오는 것을 확인했습니다 (11/12).

**한계**
- 2 · 3단계 "추정"은 상가정보 · 카카오에 등록돼 있는지를 본 것이지, 실제로 문을 열었는지 확인한 것이 아닙니다.
- 유사도 0.8 / 0.5, 거리 100m는 임시로 정한 값입니다. 근거 논문이나 공식 기준은 없습니다.
- 마트 안 코너처럼 카카오 지도에 따로 안 나오는 매장은 '폐업(추정)'으로 잘못 나올 수 있습니다.

## 7. 매일 자동 갱신 (11/13 완성)

**매일 오전 9시 30분**, 이재훈 PC에서 사람 손 없이 아래 순서로 돕니다. 약 2분 걸립니다.

```
① 인허가 3종 받기        행안부 대구 지역별 파일 (브라우저 없이)
② 검증 · 정리            10/28 자료와 대조, 좌표 변환, 영업연수 계산
③ 자동 판정              상가정보 대조 → 카카오 검색(새 가게 · 상호 바뀐 가게만)
④ 조원 판정 합치기       공유 작업판에서 그날까지 쌓인 판정을 읽어 옴
⑤ 기본 파일 · 아카이브   대구_음식점_기본.csv, 가게별 근거 파일
⑥ 팀 페이지 데이터       daegu.json
⑦ 사이트 반영            팀 페이지 저장소 main 에 daegu.json 만 올림 → Vercel 이 사이트에 반영
```

**안전장치**
- 받은 파일의 열 수(39개)나 가게 수(지난번의 98~105%)가 어긋나면 저장하지 않고 멈춥니다. 어제 결과가 그대로 남습니다.
- `daegu.json`의 가게 수가 어제와 크게 다르면(전체 ±1%, 영업 ±3%) 어제 파일로 되돌리고 멈춥니다.
- 사이트에 올릴 때: 바꾸는 파일은 `daegu.json` 하나뿐, 강제 덮어쓰기 없음, 지금 사이트와 너무 다르면(전체 ±2%, 영업 ±5%) 올리지 않음, 가게 내용이 같으면 올리지 않음.
- 동시에 두 번 돌지 않게 잠금 파일을 씁니다.
- 실행할 때마다 성공 · 실패와 숫자가 `매일갱신_기록.csv`에 남습니다.

**돌리다가 찾은 문제와 고친 것**
- 행안부가 가게 기록을 고친 직후에는 그 가게의 **좌표가 비어서** 옵니다 (11/13 파일에서 180곳). 그대로 두면 멀쩡한 가게가 "좌표 없음"으로 사람 확인에 넘어가고 사이트에서도 위치가 빠집니다. → 주소가 그대로면 전에 받은 좌표를 이어 쓰게 했습니다 (175곳 복구, `좌표_기억.csv`).

**조건:** PC가 켜져 있고 로그인돼 있어야 합니다. 9시 30분을 놓치면 로그인한 뒤 바로 실행됩니다. 하루에 약 150MB씩 자료가 쌓입니다.

**사람이 해야 하는 일:** 조원들이 공유 작업판에서 가게를 확인하는 것. 확인한 만큼 다음 날 자동으로 합쳐집니다. 공유 작업판 사이트의 확인 목록을 새로 올리는 것(배포)은 직접 실행합니다.

## 11. 팀 페이지와 이어진 방식

- 팀 페이지는 `index.html`(화면과 계산)과 `daegu.json`(데이터) 두 파일로 된 사이트입니다. 코드는 깃허브 `leegeonhyeop/daegu-survival`에 있고 main이 바뀌면 Vercel이 자동으로 배포합니다.
- **데이터(`daegu.json`)**: 매일 자동으로 main에 올라갑니다 (이건협 동의, 11/13).
- **페이지 코드(`index.html`)**: main 최신 내용을 받아 내 이름 브랜치에서 고치고, PR을 올린 뒤 단톡방에 알립니다. main에 직접 올리지 않습니다.
- `daegu.json`에 넣는 가게: 서비스 대상인 영업 가게 + 폐업일이 있는 폐업 가게(비교 대상). 상호 · 주소 · 개업일이 모두 같은 중복 줄은 하나로 합칩니다. 빠진 가게의 정확한 내역은 파일 안 `meta.excl_detail`에 있습니다.
- 주인 바뀜 의심 가게는 순위에 그대로 남고 "승계" 표시만 됩니다.

## 13. 고객과 페르소나 (빅데이터 기준, 2026-11-13 확정안)

> 팀 기획서의 페르소나(정하준 · 윤미래)는 가상 설정이라 근거가 약했습니다. 한국관광 데이터랩 빅데이터(휴대전화 이동 · 카드 소비 · 내비게이션 검색 · SNS 언급, 2025.11~2026.10)로 "누가 대구에 와서 밥을 먹는가"를 보고 다시 정했습니다.
> 표기: **[계산]** 원문 값을 더하거나 나눔 · **[해석]** 추정 · **[가정]** 근거 없음 (인터뷰로 확인할 것). 출처 기호(B1~B8, S1, V)는 13-6 참고.

### 13-1. 결론

| 구분 | 집단 | 대표 페르소나 |
|---|---|---|
| **주 고객** | 차로 오는 **30~40대 가족 나들이객** (외지인) | **박성민** (가상), 38세, 경북 구미, 아내 · 아이와 주말 당일 나들이 |
| **부 고객** | 대중교통으로 오는 **20대 친구 방문객** (외지인) | **정우진** (가상), 26세, 경북 포항, 친구와 동성로 |
| 보류 | 50~60대 부부 | 돈은 많이 쓰지만 60대 이상은 인터넷으로 정보를 얻는 비율 9.7% [S1] |
| 보류 | 대구 주민 | 빅데이터에 주민의 식당 소비 항목이 없음 → 근거 없음 |

**기획서 페르소나와 달라진 점**
- 정하준(수도권 30대, 친구와 1박 2일) → 데이터와 어긋남. 수도권(경기 + 서울)은 외지 방문의 18.9% [B1 계산], 숙박 방문은 평균 15.7% [B7 계산], 30대는 친구보다 배우자(68.1%) · 자녀(51.3%)와 옴 [S1]. **박성민으로 바꿈**
- 윤미래(대구 주민 40대) → 빅데이터 근거가 없어 **보류**. 인터뷰로 근거가 생기면 다시 넣음

### 13-2. 근거가 된 빅데이터

| 연령 | 외지인 방문 비중 [B2] | 관광 카드 소비 비중 [B3] |
|---|---:|---:|
| 20대 | **21.0%** (1위) | 7.8% |
| 30~40대 | 34.6% | **46.7%** (1위) |
| 50~60대 | 28.9% | 40.0% |

(연령별 값은 남 + 여 [계산])

- 외지 방문객 거주지: 경북 50.6% (경산 16.7 · 구미 6.3 · 포항 4.0), 경기 10.4, 경남 9.3, 서울 8.5, 부산 5.1% [B1]
- 외지인 관광 소비 중 **식사 · 음료 27.8%** (그중 일반 외식 85.4%) [B4]
- 대구 안 내비게이션 목적지 검색의 **49.3%가 음식** [B5] → 차로 와서 식당을 찍고 감
- SNS 동반자 언급의 **55.8%가 가족 계열** (기타가족 · 부모님 · 자녀 · 배우자) [B6 계산]. "미식" 여행 언급은 4.3% [B6 계산] → 맛집 투어족보다 **나들이 중 한 끼를 고르는 사람**을 노림 [해석]
- 외지인이 많이 간 곳: 신세계백화점 · 아쿠아리움, 동성로, 서문시장 [B8]
