# 사업 타당성 기획 절차서 (Playbook)

> 팀이 만든 시장성 모델 엑셀(`market_model_case_student.xlsx`, 시트 9개)의 구조를 분석해 **어떤 사업 아이디어에도 쓸 수 있게 일반화한** 절차서입니다.
> 각 단계는 ① 무엇을 구하는지 ② 어떤 입력이 필요한지 ③ 결과가 타당한지 확인하는 방법 순서로 씁니다.
> 근거: 예시 엑셀의 수식·시트 구조 분석, 프로젝트 `CLAUDE.md`의 작성 규칙. 예시 엑셀의 값은 이 문서에 옮기지 않았습니다.

---

## 0. 사용 방법

### 전체 흐름

```
0 사업 정의 → 1 자료 수집 → 2 가정 설정 → 3 시장 규모 → 4 단위경제
            → 5 손익·손익분기 → 6 규모별 손익 → 7 민감도
            → 8 경쟁·포지셔닝 → 9 종합 판정
```

- 앞 단계의 결과가 뒤 단계의 입력이 됩니다. 순서를 건너뛰지 않습니다.
- 4~7단계에서 숫자가 이상하면 원인은 대개 2단계(가정) 또는 1단계(자료)에 있습니다. 그쪽으로 돌아가 고칩니다.
- 3~7단계는 사업 유형(배달, 매장, 구독, 서비스 등)이 달라도 구조가 같습니다. 바뀌는 것은 항목 이름뿐입니다.

### 모든 단계에 공통으로 적용하는 규칙 (`CLAUDE.md` 8개 규칙의 요약)

| 번호 | 규칙 |
|---|---|
| 1 | 보고서의 모든 숫자는 엑셀에서 가져옵니다. 엑셀에 없는 숫자는 쓰지 않습니다. |
| 2 | 구분이 '가정'인 값은 보고서에도 "가정"이라고 밝힙니다. |
| 3 | 엑셀에 없는 내용은 지어내지 않고 '확인내용'으로 표시합니다. |
| 4 | 불리한 숫자를 빼지 않고, 낙관 시나리오만 골라 쓰지 않습니다. |
| 5 | 결론은 '가', '부', '조건부 시행' 중 하나입니다. |
| 6 | 자료는 값·기준 시점·출처·URL을 함께 적고, 못 찾으면 '미확인'으로 남깁니다. |
| 7 | 가정은 보수/기준/낙관 세 값으로 제안합니다. |
| 8 | 계산은 반드시 수식으로 하고, 계산 결과를 값으로 직접 입력하지 않습니다. |

### 엑셀 작업 방식

- 시트는 **입력(자료·가정) → 계산(시장규모·단위경제·손익) → 점검(계단표·민감도) → 해석(경쟁비교·포지셔닝)** 순서로 나눕니다.
- 입력은 두 시트에만 둡니다. 다른 시트에는 숫자를 직접 쓰지 않고 `자료`·`가정`을 참조합니다. 그래야 가정 한 칸을 바꾸면 모든 시트가 다시 계산됩니다.
- 입력 칸과 수식 칸을 색으로 구분합니다(예: 입력=파란 글씨, 다른 시트 연결=초록 글씨, 입력해도 되는 칸=노란 배경).

## 단계 0. 사업 정의와 범위 설정

### ① 무엇을 구하는가
분석 대상을 숫자로 계산할 수 있는 형태로 못 박습니다. 이 단계가 흐리면 뒤 단계의 숫자가 모두 흔들립니다.

- 누구에게(대상 고객 단위), 어디서(서비스 범위·권역), 무엇을 팔 것인가(제안 가치)
- 고객 한 단위가 무엇인지(개인·세대·사업장·계정)
- 비교할 실행 방안(예: 방안 A와 방안 B). 방안이 둘 이상이면 처음부터 같은 구조로 나란히 둡니다.
- 시나리오 세 개(보수·기준·낙관)

### ② 어떤 입력이 필요한가
| 입력 | 설명 |
|---|---|
| 사업 한 줄 정의 | "누구의 어떤 불편을 어떤 방식으로 해결한다" |
| 고객 단위 | 시장 규모를 셀 때 쓰는 단위. 이후 모든 비율의 분모가 됨 |
| 서비스 범위 | 지역, 채널, 기간 등 경계 |
| 실행 방안 후보 | 비용 구조가 다른 방안(전용 vs 공유, 직영 vs 위탁 등) |

### ③ 타당성 확인
- [ ] 고객 단위를 한 문장으로 말할 수 있다. (예: "우리 고객 1단위 = ○○")
- [ ] 범위의 경계가 명확해서 외부 자료(통계)를 같은 경계로 맞출 수 있다.
- [ ] 방안별로 "무엇이 다른지"가 비용 항목으로 설명된다. 설명이 안 되면 방안이 아니라 같은 안의 변형이다.
- [ ] 이 사업이 풀려는 문제를 겪는 고객이 실제로 있다는 근거가 있다. 없으면 '확인내용'으로 표시한다.

## 단계 1. 자료 수집 (자료 시트)

### ① 무엇을 구하는가
모델에 들어갈 **외부 사실 숫자**를 원문 출처와 함께 모읍니다. 이 시트의 숫자는 의견이 아니라 확인한 사실만 담습니다.

### ② 어떤 입력이 필요한가
항목마다 **7개 열**을 채웁니다.

| 열 | 내용 |
|---|---|
| 항목 | 무엇의 숫자인가 |
| 값 | 숫자 (숫자 서식으로 저장) |
| 단위 | 원, 세대, %, 건 등 |
| 기준 시점 | 조사·집계 시점 |
| 출처 | 기관·문서명·발행일 |
| URL | 원문 주소 |
| 비고 | 정의 차이, 반올림 여부, 갱신 필요 여부 |

**일반적으로 필요한 자료 묶음**

| 묶음 | 예 | 쓰이는 단계 |
|---|---|---|
| 모집단 크기 | 서비스 권역의 고객 단위 수, 전체 모집단 수 | 3 |
| 시장 규모 | 업계 전체 시장 규모 | 3 |
| 이용 행태 | 이용률, 1회 평균 지출 | 2·3 |
| 선두 사업자 실적 | 매출, 주문·건수, 거점 수 | 3 (교차 확인) |
| 비용 단가 | 최저임금, 임대료, 외주 단가 | 2·5 |
| 경쟁 정보 | 경쟁사 가격·서비스 조건 | 8 |

### ③ 타당성 확인
- [ ] 모든 행에 값·기준 시점·출처·URL이 있다. 못 찾은 항목은 빈칸이 아니라 '미확인'이다.
- [ ] **정의가 모델과 맞는다.** 단위(개인 vs 세대), 범위(전체 vs 단독), 기간(연 vs 월)이 다르면 비고에 적고 변환 방법을 정한다.
- [ ] **합계가 맞는다.** 하위 항목(예: 지역별 숫자)의 합이 상위 합계 칸과 같다. 합계는 수식으로 건다.
- [ ] **기준 시점이 너무 오래되지 않았다.** 오래된 값은 비고에 표시하고, 쓸 수밖에 없으면 보정 방법(예: 물가 반영)을 수식으로 보인다.
- [ ] **서로 다른 출처의 숫자가 충돌하면** 모두 적고, 쓰는 값과 이유를 비고에 적는다.
- [ ] 반올림·추산·보도 인용 값은 비고에 표시하고 원문 확인 계획을 적는다.
- [ ] 같은 숫자를 다른 출처로 한 번 더 대조했다(최소한 중요 숫자는).

## 단계 2. 가정 설정 (가정 시트)

### ① 무엇을 구하는가
자료로 확인되지 않는 **사업 변수**를 보수/기준/낙관 세 값으로 정리합니다. 모델의 모든 입력이 이 시트로 모입니다.

### ② 어떤 입력이 필요한가
**열 구성**: 항목 · 단위 · 보수 · 기준 · 낙관 · 구분 · 근거

**구분을 반드시 붙입니다.**

| 구분 | 의미 | 보고서 표기 |
|---|---|---|
| 자료 | `자료` 시트에서 가져온 확인된 값 (수식으로 연결) | 출처 표기 |
| 설정 | 사업 조건으로 정해 둔 값 (계약·정책·주어진 조건) | 설정값 |
| 가정 | 근거가 약해서 검증이 필요한 값 | **"가정"이라고 반드시 명시** |
| 계산 | 다른 가정에서 계산되는 값 | 수식 |

**일반적인 변수 묶음**

| 묶음 | 변수 예 |
|---|---|
| 수요 | 대상 고객 수, 이용률, 우리 서비스 선택 비율, 월 이용 횟수, 객단가 |
| 주문 1건의 비용 | 매출총이익률, 할인·프로모션, 결제 수수료, 배송·전달 비용, 포장·소모품, 세금 순부담, 폐기·손실 |
| 인건비 | 시급(자료), 법정 가산율, 사업주 부담률, 1인 처리 능력, 가동률, 최소 인원 |
| 고정비 | 임차, 관리, 관리자 급여, 에너지, 시스템, 설비 상각, 마케팅, 기타 |
| 교차 확인용 | 기존 고객 기반 규모 등 비교 기준 |

### ③ 타당성 확인
- [ ] 모든 가정이 **보수 ≤ 기준 ≤ 낙관** 순서다. (비용 항목은 보수가 더 큰 값이므로 반대 방향 규칙을 사전에 정한다.)
- [ ] 구분이 '가정'인 값은 근거 칸에 **왜 이 값인지**와 **무엇으로 검증할 것인지**가 적혀 있다.
- [ ] 가정 중 **가장 근거가 약한 것 3개**를 지목해 두었다. 이 값들이 민감도(7단계)에서 크게 움직이면 사업 판단의 핵심 불확실성이다.
- [ ] 가정 값이 자료에서 직접 나온 경우에는 값을 다시 입력하지 않고 `자료`를 참조하는 수식이다.
- [ ] 단위가 일관된다(원/월/건/%, 시간/일). 월 기준 가정과 일 기준 가정이 섞여 있지 않은지 본다.
- [ ] 시나리오 간 차이가 너무 좁거나(세 값이 거의 같음) 너무 넓지 않다(낙관이 보수의 10배 등).

## 단계 3. 시장 규모 추정 (시장규모 시트)

### ① 무엇을 구하는가
**우리가 현실적으로 얻을 수 있는 매출 규모**를 세 가지 방법으로 구하고 서로 맞춰 봅니다.

| 방법 | 질문 | 계산 구조 |
|---|---|---|
| 하향식 | 큰 시장에서 우리 몫은? | 전체 시장(TAM) × 우리 권역 비중 = 권역 시장(SAM) |
| 상향식 | 고객을 하나씩 세면? | 대상 고객 수 × 이용률 × 선택 비율 × 월 이용 횟수 × 객단가 = 월 매출 → × 12 = 연 매출(SOM) |
| 유사 사례 | 이미 하는 곳은 얼마나 파는가? | 선두 사업자 거점 1곳 평균 매출 등과 비교 |

### ② 어떤 입력이 필요한가
- 자료: 전체 시장 규모, 권역 및 전체 모집단 크기, 선두 사업자 매출·거점 수·건수
- 가정: 이용률, 선택 비율, 월 이용 횟수, 객단가 (보수/기준/낙관)

### ③ 타당성 확인 (교차 확인)
- [ ] **상향식 연 매출 ÷ 하향식 권역 시장** 값을 본다. 이 비율이 우리가 가정한 선택 비율과 **비슷한 크기**여야 정상이다. 크게 어긋나면 이용률·객단가 가정이나 TAM 정의에 문제가 있다.
- [ ] **우리 월 매출 ÷ 선두 사업자 거점 1곳 평균 월 매출**이 100%를 넘지 않는다. 후발 사업자가 선두 평균을 넘는 가정은 대개 틀린 가정이다.
- [ ] **월 이용 고객 ÷ 기존 고객 기반(회원 등)** 이 현실적이다. "기존 고객 몇 명 중 한 명이 매달 이용해야 하는가"로 읽는다.
- [ ] **객단가를 외부 실적으로 대조**한다(선두 사업자 매출 ÷ 건수). 설문 응답값은 실제 결제액보다 높게 나오는 경향이 있으므로, 둘의 차이가 크면 낮은 쪽을 기준으로 놓는다.
- [ ] 일 주문 수가 운영 현실과 맞는다(처리 가능한 인원·공간으로 소화 가능한가).
- [ ] 하향식이 지역별 이용 강도 차이를 무시한다는 한계를 본문에 적었다.

## 단계 4. 단위경제 (단위경제 시트)

### ① 무엇을 구하는가
**1건(1명, 1회)의 거래에서 남는 돈**을 구합니다. 규모가 커져도 이 값이 마이너스면 사업은 커질수록 손해입니다.

**표준 구조(위에서 아래로 빼 나감)**

```
객단가
 × 매출총이익률          = 매출총이익
 − 할인·프로모션
 − 폐기·손실
 − 결제 수수료
 − 순 전달비 (외주비 − 고객 부담분)
 − 포장·소모품
 − 세금 순부담 (빠뜨리기 쉬움)
 ─────────────────────────
 = 변동비 차감 후 공헌이익
 − 건당 인력비 (완전 가동 기준)
 ─────────────────────────
 = 인력비 차감 후 공헌이익  ÷ 객단가 = 공헌이익률
```

방안(A·B)별, 시나리오(보수·기준·낙관)별로 같은 표를 나란히 둡니다.

### ② 어떤 입력이 필요한가
단계 2의 "주문 1건의 비용"과 "인건비" 묶음 전체. 방안마다 달라지는 항목(예: 폐기율, 1인 처리 능력, 가동률)을 방안별로 따로 둡니다.

### ③ 타당성 확인
- [ ] 비용 항목마다 **부호가 맞다.** 비용은 빼는 방향이고 수수료·전달비·세금이 빠짐없이 있다.
- [ ] **빠뜨리기 쉬운 항목**을 점검했다: 세금 순부담, 결제 수수료, 폐기·손실, 고객이 내는 전달비(수익 쪽에서 차감되는 순액인지).
- [ ] **세 시나리오 중 하나라도 공헌이익이 음수면 눈에 띄게 표시**하고 보고서에 쓴다. 음수는 숨기지 않는다.
- [ ] 공헌이익률이 업종 상식 범위인가? 극단적으로 높거나(30% 초과) 낮으면(−20% 미만) 입력 오류부터 의심한다.
- [ ] 인건비를 건당으로 환산한 값이 1인 처리 능력 가정과 모순되지 않는다.
- [ ] 변동비 합이 객단가보다 크지 않은지 확인한다(그러면 팔수록 손해).

## 단계 5. 손익과 손익분기 (손익 시트)

### ① 무엇을 구하는가
월 영업손익과, **일 주문이 몇 건이어야 적자를 벗어나는지**를 구합니다.

**구조**
```
월 주문 수 × 건당 공헌이익(인력비 차감 전) = 공헌이익 합계
− 인력비 (필요 인원 × 시급 × 시간 × 일수)
− 기타 고정비
= 월 영업손익 → × 12 = 연 영업손익, ÷ 월 매출 = 영업이익률
```
- **필요 인원은 계단식**입니다: 일 주문 수 ÷ 1인 하루 처리 능력을 올림한 값과 최소 인원 중 큰 값. 주문이 조금 늘어도 인원이 한 명 늘면 비용이 한꺼번에 뜁니다.
- **손익분기 일 주문 수** = 기타 고정비 ÷ 건당 공헌이익(인력비 차감 후) ÷ 30. 공헌이익이 0 이하면 '도달 불가'.

### ② 어떤 입력이 필요한가
- 단계 3의 월 주문 수, 단계 4의 건당 공헌이익
- 1인 처리 능력(시간당 건수 × 투입 시간 × 가동률), 최소 인원
- 고정비 항목 전체, 설비 투자와 상각 연수(월 상각 = 투자 ÷ 연수 ÷ 12)

### ③ 타당성 확인
- [ ] **'도달 불가'와 적자를 있는 그대로 보고한다.**
- [ ] **현재 주문 ÷ 손익분기 주문**이 1 이상이면 흑자 구간이다. 시나리오별로 이 비율을 같이 표시한다.
- [ ] 필요 인원이 계단식으로 증가하고 최소 인원이 반영되어 있다. (인원 수가 소수로 나오면 오류)
- [ ] 방안별 고정비 구성이 다르게 들어가 있다(방안 B가 임차·설비를 안 쓴다면 그 항목이 빠져 있어야 함).
- [ ] 월 손익 합계를 손으로 한 번 검산한다(공헌이익 − 인력비 − 고정비).
- [ ] 단계 3의 일 주문 수와 손익의 일 주문 수가 같은 값이다(연결 오류 점검).
- [ ] 한 줄 손익분기 공식은 근사치임을 인지한다. 정확한 값은 단계 6에서 확인한다.

## 단계 6. 규모별 손익 (계단표 시트)

### ① 무엇을 구하는가
일 주문 수를 50, 100, 150… 식으로 바꿔 가며 **인원 계단을 반영한 월 손익**을 봅니다. 정확한 손익분기 구간과 "규모가 커지면 오히려 손해가 나는 구간"을 찾습니다.

### ② 어떤 입력이 필요한가
- 기준 시나리오의 건당 공헌이익, 처리 능력, 고정비 (모두 앞 시트 참조)
- 일 주문 수 목록(직접 입력, 사업 규모에 맞게 조정)

### ③ 타당성 확인
- [ ] 계단표의 기준 값이 손익 시트의 같은 일 주문 수 결과와 같다(한 줄이라도 대조).
- [ ] **손익이 규모에 따라 단조롭게 늘지 않는 구간**(인원이 한 명 늘며 일시적으로 손익이 꺾이는 구간)을 찾아 기록한다. 이 구간이 현실의 운영 위험이다.
- [ ] 일 주문 수 목록이 시장규모 단계의 보수~낙관 범위를 포함한다.
- [ ] 방안별로 손익분기에 필요한 규모와 우리 예상 규모의 거리를 한 줄로 요약했다.

## 단계 7. 민감도 분석 (민감도 시트)

### ① 무엇을 구하는가
**가정 하나만 ±20% 바꿨을 때 월 손익이 얼마나 움직이는지** 봅니다. 결과를 가장 크게 좌우하는 가정이 무엇인지, 그래서 어디부터 검증해야 하는지를 알려 줍니다.

### ② 어떤 입력이 필요한가
- 기준 시나리오의 가정 전체
- 변화 폭(기본 ±20%)과 대상 변수 목록(수요·가격·마진·비용·생산성 변수를 골고루)
- 한 케이스마다 모델 계산을 한 줄로 다시 수행하는 구조(변수 열 → 월 주문 → 건당 이익 → 필요 인원 → 월 손익)

### ③ 타당성 확인
- [ ] **기준 케이스의 월 손익이 손익 시트의 기준 값과 정확히 같다.** 다르면 민감도 행 수식이 모델과 어긋난 것이다.
- [ ] **변화 폭이 큰 순서로 정렬**해 상위 3개를 뽑는다. 이 3개가 사업의 핵심 가정이다.
- [ ] 핵심 가정이 단계 2에서 **근거가 약하다고 지목한 가정**과 겹치는지 본다. 겹치면 가장 위험한 가정이다.
- [ ] **움직이지 않는 가정을 해석한다.** 계단식 인건비 때문에 수요를 바꿔도 손익이 거의 안 변하는 경우가 있다. 오류가 아니라 구조 때문일 수 있으므로 원인을 적는다.
- [ ] 같은 변수의 −20%와 +20%가 손익을 반대 방향으로 움직인다(변수 방향 확인).
- [ ] 손익이 음수에서 양수로 바뀌는 변수를 따로 표시한다(그 변수가 판정을 뒤집는다).

## 단계 8. 경쟁 분석과 포지셔닝 (경쟁비교·포지셔닝 시트)

### ① 무엇을 구하는가
고객이 **우리 대신 쓸 수 있는 모든 대안**과 비교해 우리의 자리가 있는지 판단합니다. 숫자 모델이 "돈이 남는가"를 본다면, 이 단계는 "고객이 우리를 고를 이유가 있는가"를 봅니다.

**1) 경쟁 대안을 네 층으로 나눕니다.**

| 층 | 의미 |
|---|---|
| 직접 | 같은 고객에게 같은 문제를 같은 방식으로 푸는 곳 |
| 간접 | 같은 문제를 다른 방식으로 푸는 곳 |
| 대체재 | 문제 자체를 다른 행동으로 해결하는 것 |
| 현상 유지 | 아무것도 안 하고 참는 것 |

**2) 포지셔닝 축을 채점해서 고릅니다.** 축 후보 3쌍을 아래 세 기준으로 1~5점 채점하고 합계가 가장 높은 쌍을 씁니다(동점이면 위쪽 후보).
- 고객이 실제로 보는 기준인가
- 두 축이 서로 독립인가
- 근거로 위치를 정할 수 있는가

**3) 선택된 축으로 점수표 → 맵 → 빈 자리 해석** 순서로 갑니다. 점수표를 먼저 확정하고 그림을 봅니다.

### ② 어떤 입력이 필요한가
- 대안별 대상 고객, 핵심 가치, 가격·조건 (단계 1의 경쟁 정보)
- 축 후보 3쌍과 채점
- 대안별 축 점수 1~5와 점수 근거
- **모든 문장에 태그**: `[F]` 확인한 사실 · `[I]` 해석 · `[U]` 미확인(현장·앱 화면 확인 필요)

### ③ 타당성 확인
- [ ] **점검 질문: 우리 점을 지우고 봐도 축이 의미 있는가?** 우리를 빼면 경쟁자들이 두 축에서 갈리지 않으면 좋은 축이 아니다.
- [ ] **같은 점수를 받은 경쟁자 수**를 센다. 우리와 같은 칸에 경쟁자가 많으면 그 축으로는 차별되지 않는다.
- [ ] **가장 가까운 직접 경쟁자와의 점수 차이**를 본다. 작을수록 빈 자리가 아니다.
- [ ] **빈 자리는 "왜 비었는가"를 반드시 적는다.** 수요가 없어서 비었다면 기회가 아니라 함정이다.
- [ ] `[U]`·`[I]` 비율이 높은 대안이 많으면 판정을 보류하고 확인 계획을 쓴다.
- [ ] 채점은 근거를 먼저 쓰고 점수를 준다. 우리에게 유리한 쪽으로만 점수를 주지 않았는지 다른 팀원이 교차 점검한다.
- [ ] 우리의 차별점 후보가 해석(`[I]`)에 머물러 있다면 '확인내용'으로 표시하고 확인 방법(파일럿·인터뷰)을 적는다.

## 단계 9. 종합 판정

### ① 무엇을 구하는가
앞 단계의 결과를 모아 **'가', '부', '조건부 시행' 중 하나**로 결론을 냅니다. 결론에는 근거 숫자(셀 주소)와, '조건부 시행'이라면 **구체적인 조건**이 붙습니다.

### ② 어떤 입력이 필요한가
| 입력 | 출처 단계 |
|---|---|
| 시나리오별 월 영업손익, 영업이익률 | 5 |
| 손익분기 일 주문 수와 현재 주문 ÷ 손익분기 비율 | 5, 6 |
| 건당 공헌이익이 음수인 시나리오 | 4 |
| 핵심 가정 3개와 그 근거 수준 | 2, 7 |
| 교차 확인 결과(시장·선두 사업자·기존 고객 기반) | 3 |
| 경쟁 우위 판단과 미확인 항목 | 8 |

### ③ 타당성 확인 — 판정 규칙

**판정 기준은 숫자를 보기 전에 정해 둡니다**(결과를 보고 기준을 맞추지 않기 위해). 아래는 기본 제안이며 팀이 수정합니다.

| 판정 | 기본 제안 기준 |
|---|---|
| **가** | 기준 시나리오가 흑자이고 **보수 시나리오도 큰 손실이 아니며**, 핵심 가정이 검증 가능한 범위 안에 있고, 경쟁 우위가 `[F]`로 확인됨 |
| **조건부 시행** | 기준 시나리오는 흑자(또는 손익분기 근처)이지만 **보수에서 적자**이거나, 핵심 가정·차별점이 `[I]`·'확인내용'에 머물러 있음. **검증할 조건**과 **중단 기준**을 함께 적는다 |
| **부** | 기준 시나리오에서도 건당 공헌이익이 음수이거나, 손익분기 주문이 시장규모 낙관 값을 넘거나, 경쟁에서 설 자리가 확인되지 않음 |

확인 사항:
- [ ] **세 시나리오(보수·기준·낙관)와 두 방안(A·B)을 모두 보고서에 넣었다.** 기준만 쓰지 않는다.
- [ ] **불리한 숫자(적자, 도달 불가, 음의 공헌이익)가 본문에 있다.**
- [ ] 결론이 '조건부 시행'이면 조건이 **측정 가능한 문장**이다. (예: "첫 90일 안에 일 주문 ○건 이상", "선택 비율 ○% 이상")
- [ ] 결론의 근거 숫자마다 셀 주소를 붙였다.
- [ ] 구분이 '가정'인 값에 의존한 결론은 "가정에 기초한 결론"이라고 적었다.
- [ ] 엑셀에 없는 내용은 '확인내용'으로 남겼다.
- [ ] 승인은 사용자가 한다. 작성 담당과 검토 담당은 결론을 제안만 한다.

## 부록 D. 예시 엑셀을 분석하며 확인한 보완 의견

예시 엑셀에는 좋은 설계가 많습니다(입력 시트 분리, 3개 시나리오, 구분 열, 교차 확인, 손익의 계단식 인원). 동시에 **다음 사업에 쓸 때 보완하면 좋은 점**이 보였습니다.

| 번호 | 보완 의견 | 이유 | 제안 |
|---|---|---|---|
| 1 | **교차 확인이 순환될 수 있습니다** | 객단가를 선두 사업자 실적에서 역산해 검증하는 칸이 있는데, 2025년 값을 모를 때 같은 값을 가정에 쓰면 비교 결과가 항상 같아져 검증 기능이 사라집니다 | 교차 확인용 값은 **가정의 근거와 독립적으로** 구한다. 독립 자료가 없으면 해당 확인은 '확인내용'으로 표시 |
| 2 | **초기 투자 회수 계산이 없습니다** | 설비 투자는 월 상각비로만 들어가 있어 "투자금을 몇 달에 회수하는가", "자금이 언제 가장 부족한가"를 알 수 없습니다 | 월별 현금흐름 표(초기 투자, 램프업, 누적 현금)와 회수 기간을 추가 |
