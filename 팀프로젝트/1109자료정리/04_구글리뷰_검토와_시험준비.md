# 구글 리뷰 검토와 시험 준비

> 표기: **[사용자]** = 사용자가 정한 내용, **[AI 판단]** = Claude의 판단이나 제안
> 확인 수준: 구글 공식 문서를 웹 검색 결과로 확인했습니다. 실제 호출과 한국 요금은 아직 확인하지 않았습니다.

## 1. 제안

**[사용자]** "구글은 외국인 리뷰가 많고, API로 받아올 수 있어서 좋을 것 같다"

## 2. 공식 문서에서 확인한 것 (Places API New)

| 항목 | 내용 |
|---|---|
| 리뷰 | 곳당 **최대 5개**, 관련도순 |
| 평점·리뷰 수 | 전체 평점(`rating`)과 전체 건수(`userRatingCount`)만 있음. 언어별 수치 칸은 찾지 못함 |
| 언어 | 리뷰마다 원문 언어 코드가 있음 |
| 저장 | 장소 ID 외의 리뷰·상세 정보는 사전 수집, 저장 금지 |
| 지도 | 지도에 결과를 표시하려면 구글 지도 사용 |
| 출처 표시 | 작성자 정보 등 표시 필수 |
| 비용 | 리뷰를 요청하면 높은 요금 등급. 결제 수단 등록 필요. 무료 사용량은 SKU별로 월 단위로 있음 |

## 3. 판단

**[AI 판단]** 판정 기준으로는 맞지 않고, 카드에 보여 주는 참고 정보로는 쓸 수 있습니다.

| 문제 | 내용 |
|---|---|
| 외국인 비율을 알 수 없음 | 리뷰 5개만 오고, 전체 건수는 언어 구분이 없음 |
| 판정표에 저장하기 어려움 | 약관상 리뷰·평점 저장 금지 |
| 서비스 개념과 차이 | 2·3단계는 "동네"의 선택. 외국인 리뷰는 관광객의 반응 |
| 확인 안 된 가정 | 동네 노포에 외국인 리뷰가 많은지는 대구 자료로 확인한 적 없음 |

**좋은 점:** 공식 API라 비공식 경로인 카카오 크롤링보다 근거가 깔끔합니다. 가게별 시민 반응 자료가 없다는 빈틈도 일부 메울 수 있습니다.

**쓰는 방식 제안**
- 판정과 순위에는 넣지 않습니다.
- 사용자가 카드를 열 때 구글 평점과 리뷰를 실시간으로 불러오고, 저장은 장소 ID만 합니다.
- 어떤 지도를 쓸지와 함께 정합니다.

## 4. 시험 준비 (11/09)

**[사용자]** "네, 시험해 보자"

| 항목 | 내용 |
|---|---|
| 표본 | 중구 60곳 (상위 30 / 비교 30, `1105자료정리` 13번 문서와 같은 표본) |
| 찾기 | 상호로 검색, 우리 좌표 150m 안이고 이름 유사도 0.6 이상만 연결 |
| 보는 것 | 연결률, 리뷰 수, 받은 리뷰 중 외국어 비율, 카카오와 평점 차이 |
| 저장 | `구글_장소ID_중구.csv` (장소 ID와 연결 여부), `구글_시험요약_중구.csv` (집단별 요약만) |
| 안전장치 | 호출 최대 130회, 요청 간격 1초 |
| 스크립트 | `step10_google_test.py` (문법 확인까지만 함) |

**시험의 한계:** 받은 리뷰 5개는 관련도순이라 외국인 비율을 대표하지 않습니다.

## 5. 사용자가 할 일

1. Google Cloud 콘솔에서 프로젝트를 만들고 결제 계정을 연결합니다(카드 등록).
2. Places API (New)를 사용 설정합니다.
3. API 키를 만들고, 키 제한에서 Places API (New)만 허용합니다.
4. PowerShell에서 `setx GOOGLE_PLACES_KEY "키"`로 저장합니다. 키는 채팅이나 파일에 적지 않습니다.
