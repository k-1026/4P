# 규칙 · 제도 정리 — 다른 지도 앱의 정보를 가져다 보여 줘도 되나 (2026-11-19)

> 질문 종류: ⑥ 규칙 · 제도 (`../출처_등급_기준.md`) — A = 법령 · 약관 원문, B = 기관 · 회사 공식 해설, C = 기사 · 법률 블로그
> **이 문서는 조사 정리이고 법률 자문이 아님.** 서비스로 만들기 전에 약관 원문과 전문가 확인이 필요
> 확인일: 2026-11-19

## 한 줄 결론

세 앱 모두 **화면을 긁어 와서(크롤링) 우리 서비스에 저장 · 표시하는 방식은 막혀 있거나 위험**하다. 공식 API로 받을 수 있는 정보는 앱마다 다르고, **별점 · 리뷰를 공식으로 주는 곳은 구글뿐**이며 그것도 저장 · 표시 조건이 붙는다.

## 1. 공식 API로 받을 수 있는 것

| 앱 | 공식 API | 별점 · 리뷰 | 저장 | 등급 · 출처 |
|---|---|---|---|---|
| 네이버 | 검색 API(지역) | **없음** — 응답은 상호 · 링크 · 카테고리 · 설명 · 전화 · 지번/도로명 주소 · 좌표 | 확인 못 함 | B: [네이버 API 문서(지역 검색)](https://api.ncloud-docs.com/docs/naver-api-hub-search-local) — 예시 응답에 별점 · 리뷰 필드 없음 |
| 카카오 | 로컬 API(키워드 장소 검색) | **확인 못 함** (우리가 쓰는 응답에는 별점 없음 — `02_자동판정/카카오검색_캐시.jsonl`) | **저장해서 반복 사용 불가, 실시간 호출로만** | B: 카카오 개발자 포럼의 운영자 답변 ([1](https://devtalk.kakao.com/t/api/150800), [2](https://devtalk.kakao.com/t/local-api/151190)) — 공식 정책 문서 원문은 아직 못 읽음 |
| 구글 | Places API | **있음** — 별점 · 리뷰 수 · 리뷰 최대 5개 | **미리 받아 두기 · 캐싱 · 저장 금지** (place_id만 예외) | A: [Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies) |

구글 Places API 표시 조건 (A, 같은 문서)
- 지도 위에 보여 줄 때는 구글 지도여야 함. 지도 없이 보여 줄 때는 구글 로고와 출처 표시 필요
- 리뷰를 보여 줄 때는 작성자 이름을 가까이 표시

## 2. 화면을 긁어 오는 것(크롤링)

| 근거 | 내용 | 등급 |
|---|---|---|
| 세 사이트의 robots.txt (직접 확인) | map.naver.com · map.kakao.com · place.map.kakao.com 모두 GPTBot · PerplexityBot 등 **AI 수집 봇을 전부 차단** | A (원문 직접 확인) |
| 네이버 이용약관 | 자동화된 프로그램으로 게시물을 무단 수집하는 것을 금지한다고 소개됨 — **조항 원문은 아직 못 읽음** | C: [이노포레스트 정리](https://www.innoforest.co.kr/report/347/) |
| 네이버 검색 API 특약 개정 | 크롤러 · 봇 · 스크립트 자동 수집, 차단 우회를 금지 대상에 포함, 2026-09-07 시행이라고 보도 — 공지 원문 확인 필요 | C: [토큰포스트](https://www.tokenpost.kr/news/ai/403521) |

## 3. 판례 (야놀자 · 여기어때, 잡코리아 · 사람인)

| 사건 | 결론 | 등급 |
|---|---|---|
| 대법원 2022.5.12. 선고 2021도1533 (형사) | 여기어때의 크롤링에 **무죄** — 이미 공개된 정보의 일부이고 수집에 큰 비용이 들었다고 보기 어렵다는 이유. 데이터베이스제작자 권리 침해 · 정보통신망법 위반 등 불인정 | C (법률 기사 요약, 판결문 원문 확인 필요): [로톡 해설](https://www.lawtalk.co.kr/posts/171714) |
| 서울고등법원 2022.8.26. 선고 2021나2034740 (민사) | 같은 행위에 **손해배상 책임 인정** — 부정경쟁방지법의 성과 도용 조항 | C (같음) |
| 잡코리아 · 사람인 | 채용 정보를 긁어 간 행위에 권리 침해 인정이라고 소개됨 | C (같음) |

읽는 법: **형사 처벌은 안 받았어도 민사 책임은 졌다.** 경쟁 서비스의 정보를 긁어 와 자기 영업에 쓰면 손해배상 위험이 있다.

## 4. 우리 프로젝트에 주는 뜻

| 하려는 것 | 판단 (조사 기준) |
|---|---|
| 세 앱의 별점을 긁어 와 나란히 보여 주기 | 위험. 네이버 · 카카오는 별점을 공식으로 주지 않고, 긁어 오는 것은 약관 · 판례상 문제 소지 |
| 구글 별점을 Places API로 보여 주기 | 가능하지만 저장 금지 · 출처 표시 조건. 대구 동네 가게의 약 27%는 구글에 없음(우리 실측) |
| 각 앱으로 **넘겨 주는 링크**(바로 가기)만 모아 주기 | 정보를 복제하지 않으므로 상대적으로 안전 — 약관 확인은 필요 |
| 주차 · 입지 같은 정보를 **공공데이터**(공영주차장 현황 등)와 우리 판정 데이터로 채우기 | 가장 안전. 공공데이터는 이용 허락 범위 안에서 저장 · 가공 가능 |
| 사용자가 직접 남긴 정보 · 우리가 직접 조사한 정보 | 문제 없음 |
| 지금 하는 조사(100곳 실측, 리뷰 3,135개 분석) | 사람 눈으로 보는 수준의 소량 조사 · 연구 목적. 서비스에 그대로 싣는 것과는 다른 문제 |
